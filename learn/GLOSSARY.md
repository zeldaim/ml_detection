## 1. ML 가장 기본

- **모델(model)**: 데이터에서 규칙을 배운 "판단기". 입력(피처)을 넣으면 출력(이상이다/정상이다)을 준다.
- **피처(feature)**: 모델에게 던지는 **질문/측정값**. 예: "이 5분에 요청 몇 번 왔나". 숫자다. → `ml/features.py`
- **라벨(label)**: **정답지**. "이 구간은 공격(bola)이었다". 사람이 사실로 기록. 피처와 다름(= 질문 vs 답). → `docs/19` §2-1
- **데이터셋(dataset)**: 피처 + 라벨을 모은 표. 모델의 교과서. → `data/dataset_web.csv`
- **학습/훈련(training, `fit`)**: 모델이 데이터셋을 보고 규칙을 익히는 것. **중요: `fit`은 덮어쓴다**(이전 걸 기억 안 함). → `docs/19` §1
- **예측/추론(predict, inference)**: 학습한 모델을 **써서** 새 입력을 판단. (학습과 다름: 학습=만들기, 예측=쓰기)
- **하이퍼파라미터(hyperparameter)**: 사람이 미리 정하는 설정값. 예: `contamination`(이상으로 볼 비율). 학습으로 안 정해짐.
- **스키마(schema)**: 표의 "열 구조"(열 이름·순서). 데이터를 쌓으려면 고정돼야 함. → `ml/accumulate.py`

## 2. 학습의 종류

- **지도학습(supervised)**: **정답(라벨)을 주고** 배움. "이건 공격, 저건 정상" 보여주며 가르침. → RandomForest. `ml/supervised.py`
- **비지도학습(unsupervised)**: **정답 없이** "평소(정상)"만 배우고, 벗어난 걸 이상이라 함. → IF·LOF·AE. 룰·라벨 없어도 처음 보는 공격을 잡는 핵심.
- **분류(classification)**: 출력이 **종류/라벨**. "정상/대입/BOLA 중 뭐냐". → RandomForest
- **회귀(regression)**: 출력이 **숫자**. "다음 5분 예상 요청 수=237". 예측(forecasting)·위험점수에 씀. → `docs/19` 회귀 설명
- **이상탐지(anomaly detection)**: "평소와 다른 것"을 찾기. 이 프로젝트의 중심. → `docs/02`, `docs/12`

## 3. 이 프로젝트가 쓰는 모델

- **Isolation Forest (IF)**: "이상한 점은 몇 번 안 잘라도 혼자 뚝 떨어진다"는 아이디어. 전체에서 **동떨어진** 점을 찾음. 약점: **느린 공격을 놓침**. → `docs/02`
- **LOF (Local Outlier Factor, 국소 이상치)**: "이웃보다 밀도가 낮으면 이상". 주변과 비교해 **국소적으로** 튀는 걸 잡음. 느린 공격에 강함. → `docs/12`
- **Autoencoder (AE)**: 입력을 **압축했다 복원**하는 신경망. 정상은 잘 복원, 이상은 복원 오차가 큼 → 그 오차로 탐지. **회귀의 일종**. 약점: 정상 분포가 바뀌면 오탐↑(분포 shift). → `docs/16`, `docs/21` §G
- **Random Forest (RF)**: 결정트리 여러 개의 투표. 여기선 **공격 종류 분류**에 씀. 약점: 학습에 없던 종류는 못 잡음. → `ml/classify_type.py`
- **One-Class SVM (OCSVM)**: 정상만으로 경계를 그려 밖을 이상이라 함. 비교군. → `ml/models.py`
- **Z-score**: "평균에서 표준편차 몇 배 벗어났나"로 이상 판정. 단순 비교군. 단변량이라 느린 공격 놓침.
- **contamination**: IF·LOF·AE에게 "데이터의 몇 %를 이상으로 보라"고 주는 설정. 낮추면 오탐↓(탐지도 조심). → `docs/21` §D

## 4. 성능 평가 용어

- **TP/FP/FN/TN**: 맞게 공격(TP)·정상을 공격이라 오판(FP)·공격을 놓침(FN)·맞게 정상(TN).
- **정밀도(Precision)**: 공격이라 한 것 중 진짜 비율. (오경보 적을수록 ↑)
- **재현율(Recall) = 탐지율**: 진짜 공격 중 잡은 비율. (놓침 적을수록 ↑)
- **F1**: 정밀도와 재현율의 균형 점수.
- **오탐률(False Positive Rate)**: 정상인데 공격이라 운 비율. 낮아야 좋음. → `docs/17`(정상만으로도 오탐 생김)
- **혼동행렬(confusion matrix)**: TP/FP/FN/TN을 한 표로. → `ml/classify_type.py`
- **피처 중요도(feature importance)**: RF가 "어느 피처를 많이 썼나". 쓸모없는 피처 빼는 근거. → `ml/supervised.py` 출력
- **교차검증(cross-validation)**: 데이터를 나눠 "안 본 것"으로 평가. 과적합 숨기지 않기.
- **leave-one-group-out**: 공격 묶음(종류/사건)을 하나씩 빼고 학습 → "처음 보는 공격"을 잡나 측정(E2). → `ml/supervised.py`
- **held-out(봉인셋)**: 끝까지 안 건드리고 최종 시험에만 쓰는 데이터. 거기 맞춰 튜닝하면 반칙. → `docs/21` §7

## 5. 데이터·플라이휠·함정

- **플라이휠(flywheel)**: 탐지→라벨→축적→재학습을 돌리며 **데이터를 쌓아** 모델을 키우는 선순환. → `docs/19` §4
- **재학습(retraining)**: 쌓인 데이터 전체로 **다시** 학습(덮어쓰기라 매번 전체로).
- **증분/온라인 학습(partial_fit)**: 기존 모델에 **이어서** 배우는 방식(이 프로젝트는 안 씀, 배치 재학습).
- **합성 데이터(synthetic)**: 내가 만들어낸 가짜 데이터. 개발·연습엔 OK, **검증엔 못 씀**(내 가정이라서). → `docs/19` §7
- **데이터 증강(augmentation)**: 변주를 더 만들어 넓이 보강. 단 검증은 실제로.
- **sim-to-real 격차**: 합성(가상)에서 잘 되던 게 실제에선 뚝 떨어지는 현상. → `docs/19`
- **분포 shift(distribution shift)**: 학습 때와 실제(평가) 때 데이터 분포가 달라 성능 하락. AE 오탐 0.88의 원인. → `docs/21` §G
- **편향(bias)**: 데이터가 현실과 안 맞아 **기울어진** 판단. 양 늘려도 안 고쳐짐(다양성으로). → `docs/19` §6-1
- **분산(variance)**: 추정이 들쭉날쭉·불안정. 데이터 양 늘리면 줄어듦. → `docs/19` §6-1
- **과적합(overfitting)**: 특정 데이터(도구/환경)에 너무 맞춰져 새 것엔 실패. "그 도구를 외움".
- **일반화(generalization)**: 안 본 데이터에도 통하는 능력. 목표.
- **대표성(representativeness)**: 데이터가 실제 상황을 잘 대변하는 정도. 양보다 중요.
- **클래스 불균형(class imbalance)**: 정상 많고 공격 적음 → 지표 흔들림·희귀 종류 무시.
- **라벨 누수(label leakage)**: 정답을 몰래 포함한 피처(예: 공격자 IP·UA)로 학습 → 가짜로 완벽. 금지. → `docs/17`
- **지름길 학습(shortcut learning)**: 진짜 원인 대신 손쉬운 표식(환경 특이값)을 외우는 것.
- **퍼뮤테이션 검사(permutation test)**: 라벨을 무작위로 섞어 "모델이 진짜 신호를 배우나 vs 고장인가" 확인. → `docs/21` §C 근처(모델 건강 검사)

## 6. 피처 계산에 쓰인 수학

- **구간/윈도우(window)**: 로그를 "출발지 × 5분"으로 묶은 한 칸 = 표의 한 줄. → `ml/features.py`
- **엔트로피(Shannon entropy)**: 분포가 얼마나 고른가. 한 경로만 두드리면 낮음(스캐너). → `endpoint_entropy`
- **변동계수(CV) = `interval_cv`**: 요청 간격의 (표준편차/평균). 0에 가까우면 **기계처럼 일정**(봇).
- **정규화/스케일링(normalization)**: 피처 숫자 크기를 맞춰 모델이 공평히 보게. (LOF 등 거리 기반에 필수)
- **경로 템플릿화(path templating)**: `/basket/6`, `/basket/7` → `/basket/{id}`로 묶기. 숫자·UUID 모두. → `ml/features.py`
- **uniq_objects**: 남이 보면 안 되는 자원의 서로 다른 ID 수 = BOLA 징후.

## 7. 보안·공격 용어 (OWASP API Top 10 중심)

- **OWASP**: 웹/API 보안 표준을 만드는 단체. "API Top 10" = 흔한 API 취약점 목록.
- **BOLA (API1, 객체 수준 권한 미흡)**: 남의 자원 ID를 바꿔 **남의 데이터 열람**. 예: `/basket/7`로 남 장바구니. → `uniq_objects`
- **Broken Authentication (API2) / 무차별 대입(brute force)**: 비번/OTP를 **반복 시도**. → `max_req_1min`, `err_ratio`
- **credential stuffing**: 유출된 여러 계정으로 대입. → `uniq_users`↑
- **BFLA (API5, 기능 수준 권한 미흡)**: 일반 사용자가 **관리자 기능** 호출. 단발이라 행위로 잘 안 튐(대조군).
- **Mass Assignment / 과다 데이터 노출**: 숨겨야 할 필드 조작·대량 응답. 내용형(대조군).
- **열거(enumeration)**: ID·사용자를 **순차로 긁기**(1,2,3…). BOLA·수집의 전형.
- **SQLi (SQL Injection)**: 쿼리에 악성 구문 주입. 탐지 토큰: UNION·주석·`information_schema`·`sleep()`. → `edge/db_features.py`
- **SSRF**: 서버가 공격자가 시킨 내부 주소로 요청하게. (내용형)
- **스캐닝/강제 브라우징**: 없는 경로를 마구 찔러봄 → 404 폭증. → `status_404_ratio`(제안 피처)

## 8. 인프라·수집 용어

- **nginx**: 웹 서버/리버스 프록시. 여기선 :80에서 받아 Juice Shop(:3000)로 넘기고 **접근 로그**를 남김.
- **리버스 프록시(reverse proxy)**: 앱 앞에 서서 요청을 대신 받아 전달. 로그·보안 지점.
- **access log / combined 형식**: 접근 기록. "IP - - [시각] \"메서드 경로\" 상태 크기 ...". features.py 입력.
- **remote_addr**: 로그에 찍히는 **출발지 IP**. 앱 로그 기반이라 "출발지"는 이 필드값. → `docs/21` §G
- **IP 별칭(alias)**: 한 머신에 IP를 여러 개 붙이기. 여러 출발지를 흉내낼 때. (실제 트래픽 다중 IP 생성에 사용)
- **Juice Shop**: OWASP가 만든 **일부러 취약한** 연습용 쇼핑몰 앱. 랩에서만.
- **Wazuh**: 오픈소스 보안 모니터링(SIEM 계열). `alerts.json`(경보)·`archives.json`(전체 이벤트). → `docs/01`, `docs/08`
- **SIEM**: 로그를 모아 보안 이벤트를 분석하는 시스템(Wazuh·ELK 등).
- **DAM / UEBA**: DB 활동 모니터링 / 사용자·개체 행위 분석. → `docs/22`
- **joblib / scikit-learn / pandas**: 모델 저장 / ML 라이브러리 / 표 분석 라이브러리.
- **(crapi-lab 쪽) kind·Cilium·Hubble·eBPF·L7·NodePort·Terraform**: 쿠버네티스 랩 도구들. 이 프로젝트의 **다음 phase 인프라**(지금은 보류). → `D:\crapi-lab`

## 9. LLM 용어

- **LLM(대규모 언어모델)**: ChatGPT·Claude 같은 언어 AI. 여기선 **판정자가 아니라 참모**로만(설명·추천). → `ml/explain_llm.py`
- **프롬프트 인젝션(prompt injection)**: 입력에 숨긴 지시로 LLM을 조종. 로그 속 공격 문자열이 LLM 지시로 둔갑 위험.
- **로그 인젝션**: 공격자가 로그에 악성 문자열을 심음(→ 프롬프트 인젝션으로 이어짐).
- **비결정성(nondeterminism)**: 같은 입력에도 LLM 답이 달라짐. 그래서 최종 판정은 룰·점수가.
- **비식별화/마스킹/토큰화**: 민감값을 지우거나 `?`·가명으로 치환. (피처화 자체가 비식별화)
- **no-train / 무보존**: 보낸 데이터를 학습·저장에 안 쓰겠다는 계약 조건.
- **구조화 출력(structured output)**: LLM이 정해진 형식(예: block/observe/ignore 중 하나)만 뱉게 제한.
