# 검증 보고서 — "AI 생성 코드 함정" 비판에 대한 증거 기반 반증/인정

> 외부 비판(AI가 급조한 ML 레포가 흔히 가진 문제: 데이터 안 맞음·껍데기 파이프라인·누수/가짜100%·
> 매직넘버·예외처리 부재)을 **우리 프로젝트에 그대로 적용해 검증**. 주장이 아니라 **재현 가능한 증거**로.
> 재실행: `bash verification/verify.sh` (6/6 통과). 상세 실험: `docs/21`.

## 요약
| 비판 항목 | 판정 | 근거 |
|---|---|---|
| ① 데이터 안 맞음(context hallucination) | **반증** | 실제 nginx 로그로 end-to-end 동작(246구간, 피처 정상) |
| ② 껍데기·파이프라인 미연결 | **반증** | 로그→피처→상대피처→검증 완주 + train(train_export)→inference(predict) 연결 확인 |
| ③ 데이터 누수 / 가짜 100% | **반증** | 퍼뮤테이션(가짜공격≪진짜), IP/UA 피처 미사용, leave-one-group-out+train-until |
| ④ 매직넘버·땜질 | **대체로 OK** | contamination·window 는 문서화+스윕(§D). 임의값 아님 |
| ⑤ 예외처리·입력검증 부재 | **인정→수정함** | features.py 는 기존 처리. models/evaluate/db_features 에 **파일없음·빈파일·필수열 검증 추가**(깔끔한 에러 메시지로 종료) |

## 상세

### ① 데이터가 코드와 맞나
합성이 아닌 **실제 Juice Shop nginx 로그**로 `features.py`가 246구간×9피처를 정상 추출.
→ "그럴듯하지만 내 데이터와 안 맞는 코드"가 아님. (`verify.sh` [1])

### ② 파이프라인 연결 / 껍데기 여부
- 로그→피처→상대피처→교차검증 **에러 없이 완주**.
- **학습·추론 분리 연결**: `train_export.py`로 저장 → `predict.py`가 로드해 IF/LOF/AE/합집합 판정(exit 0).
→ "실행조차 안 되는 껍데기" 아님. (`verify.sh` [1][2])

### ③ 누수·가짜 100% (가장 중요)
AI 코드의 최대 함정. 우리는 **다층으로 차단**:
- **퍼뮤테이션 검사**: 정상 구간을 무작위로 '공격'이라 거짓 라벨 → **가짜 탐지율 ≪ 진짜 탐지율**(건강). 모델이 라벨을 외운 게 아니라 **실제 신호**를 봄.
- **누수원 차단**: IP·User-Agent·pod이름 등 식별자를 **피처로 안 씀**(행위 피처만). 라벨 누수 경로 제거.
- **분리**: `--train-until`(정상 기간만 fit) + `leave-one-group-out`(처음 보는 공격). 평가셋에 맞춰 튜닝 안 함.
- **합성 100% 해명**: 합성에서 탐지 1.00이 나온 건 **누수가 아니라 데이터가 쉬워서**(퍼뮤테이션으로 증명). 실제 데이터선 0.5~0.97로 현실적. (`docs/21` §D·F·L)
→ "겉보기 100%, 실전 무용지물"의 반대. (`verify.sh` [3][4])

### ④ 매직넘버
- `contamination`(0.1→0.01 스윕, §D), `window`(5분, 문서화), `n_neighbors`(LOF) 등은 **의미·근거 문서화**.
- 개선 여지: 일부 임계값을 상단 상수/인자로 더 노출하면 좋음(경미).

### ⑤ 예외처리·입력검증 (인정 → 수정 완료)
- `features.py`: 깨진 JSON 줄 skip, 인코딩 errors=replace, 정규식 미스 skip → 기존 OK.
- **수정함**: `models.py`·`evaluate.py`·`db_features.py` 에 **파일 없음·빈 파일·필수 열(window_start) 검증** 추가 → 잘못된 입력 시 **깔끔한 에러 메시지로 종료**(스택트레이스 크래시 대신). 스모크 테스트로 확인(나쁜 입력→명확한 에러, 정상 입력→동작 유지).
- 남은 개선: 숫자 아닌 값 등 더 세밀한 검증은 추후.

## ★ 메타: "우리(Claude+나)가 우리를 검증하는 게 말이 되나?"

정직한 답: **부분적으로만.** 자기검증은 **독립 검증이 아니다**(만든 사람이 평가 → 편향 위험). 그래서 두 가지로 보강했다:

1. **검증을 '기계/적대적'으로** 만들었다 — 사람 의견이 아니라 **데이터가 판정**:
   - 퍼뮤테이션(라벨 섞어 모델 고장 여부), leave-one-group-out(안 본 것), held-out, IP/UA 피처 배제.
   - 이건 "내가 맞다고 우긴" 게 아니라 **반증 시도가 통과한** 것.
2. **재현 가능하게** 만들었다 — `verify.sh`를 누구나 돌려 **직접** 확인. 주장→재현으로 전환.

**그래도 한계(= 진짜 독립 검증이 아님):**
- 데이터·실험·검증을 **같은 주체(이 세션)**가 설계 → 설계 자체의 맹점은 못 잡을 수 있음.
- 진짜 독립 검증 = **제3자가 다른 환경에서 재현** / **실제 운영 배포** / 외부 리뷰. → **팀 인프라·외부 리뷰 단계에서** 해야 함(미완).
- 그래서 이 보고서는 **"증거 기반·재현 가능한 자기검증"**이지 **"독립 검증 통과"가 아니다.** 발표/인수인계 시 이 구분을 명시할 것.

> 한 줄: **자기검증이라 완전하진 않지만, "주장"이 아니라 "데이터가 반증을 통과한 재현 가능한 증거"로 올렸다. 독립 검증(제3자·실환경)은 다음 단계.**
