# 11. 추가 조사 — API 보안 솔루션 · 룰 밖 이상행위 탐지 방법

> 작성일: 2026-10-23 · 상태: 조사 메모
> 목적: 우리 프로젝트(`07` 행위 층 ML)가 실무 솔루션 중 어디에 해당하는지, 룰이 놓친 이상행위를 찾는 일반적인 방법 중 무엇을 더 가져올 수 있는지 정리한다.
> 관련: `07`(메인 컨셉), `10`(7~8주차 실행 계획), `04`(SOAR)
> ⚠️ 제품명·인수합병 관계는 작성 시점 지식 기준. 이 분야는 변화가 잦으므로 **보고서 인용 전 각 제조사 공식 자료로 재확인**.

## 1. API 보안 솔루션의 종류

| 종류 | 하는 일 | 대표 예 | 우리 프로젝트 대응 |
|---|---|---|---|
| **API 게이트웨이** | 인증 확인, 레이트리밋, 라우팅 | Kong, AWS API Gateway, Apigee, Azure API Management | `07` ① 룰의 레이트리밋 |
| **WAF / WAAP** | 요청 문자열의 공격 패턴을 시그니처로 차단 | Cloudflare, AWS WAF, Akamai, F5, Imperva / 오픈소스 ModSecurity·Coraza + OWASP CRS | `07` ① 시그니처, 요청 층 |
| **API 보안 플랫폼** | 트래픽에서 API 목록 자동 발견(섀도 API 포함), API·사용자별 **평소 행동 학습** → BOLA·대량 수집 등 행위 공격 탐지 | Salt Security, Traceable, Noname(Akamai 인수), Wallarm, Cequence / 오픈소스 Akto | **`07` ② ML 행위 층** |
| **봇 관리** | 사람과 자동화 도구 구별 (스크래핑, 크리덴셜 스터핑) | Cloudflare Bot Management, Akamai Bot Manager | `07` B3·B4 |
| **API 보안 테스트** | 배포 전 취약점 점검 (명세 검사, 동적 스캔) | 42Crunch, OWASP ZAP, Burp Suite, StackHawk | 예방 계층 (탐지 범위 밖) |

**시사점**
- 게이트웨이·WAF는 **요청 1건 단위** 판정 → 문법상 정상인 BOLA 요청을 구분하지 못한다
- 그래서 **행동 기준선 + 이상 탐지**를 핵심으로 하는 "API 보안 플랫폼" 범주가 따로 생겼다
- 우리 프로젝트 = 그 원리를 **오픈소스(Wazuh + scikit-learn)로 재현**하고 룰 대비 효과를 수치로 보여주는 것

## 2. 룰이 놓친 이상행위를 찾는 일반적인 방법

| 방법 | 원리 | 잘 잡는 것 | 우리 프로젝트 |
|---|---|---|---|
| **통계 기준선** | 주체·엔드포인트별 평소 값(평균·분위수)과 비교, 동적 임계값 | 양의 급변 | `10` §3-1 Z-score |
| **비지도 ML** | 라벨 없이 분포에서 동떨어진 점 탐지 (IF, LOF, OCSVM, 오토인코더, 군집) | 피처 조합의 이상 | `10` §3-2 (핵심) |
| **UEBA** | 사용자·기기별 프로필, 자기 과거 또는 **유사 역할 동료 집단(peer group)** 과 비교 | 정상 계정의 이상 행동, 내부자 | IP별 피처가 축소판. 동료 집단 비교는 확장 후보 |
| **위험 점수 누적 (RBA)** | 저레벨 신호를 주체별 점수로 누적, 임계 초과 시 경보 | 하나하나는 약한 느린 공격 | Wazuh 저레벨 알럿 + ML 점수 결합 후보 |
| **시퀀스·시계열** | 호출 순서 패턴(로그인 → 조회 → 주문), 변화점 탐지 | 정상 흐름을 건너뛰는 자동화 | 확장 후보 |
| **스태킹 (롱테일 분석)** | 값별 빈도를 세어 **가장 드문 것**부터 확인 (드문 User-Agent·경로·상태코드 조합) | 처음 보는 도구·경로 | `10` §2-5 리포트에 바로 추가 가능 |
| **위협 헌팅** | 분석가가 가설을 세우고 데이터를 직접 검색 | 자동화가 놓친 맥락 | 보고서 분석 사례 |
| **기만 기법 (카나리 객체)** | 실사용이 없는 가짜 객체 ID를 심어 두고 접근 시 즉시 경보 | **BOLA 열거**, 오탐 거의 없음 | 추천 (§3) |
| **지도 학습** | 라벨 데이터로 분류기 학습 | 알려진 공격의 변형 | CSIC 2010 요청 층 (선택, `07` §5) |

## 3. 프로젝트에 추가 검토할 항목 (우선순위)

| 순위 | 항목 | 작업량 | 기대 효과 | 들어갈 곳 |
|---|---|---|---|---|
| 1 | **스태킹 리포트** — 경로·User-Agent·상태코드별 드문 값 상위 N | 쿼리 몇 줄 | 사람이 볼 후보 목록, ML 결과 교차 확인 | `10` §2-5 |
| 2 | **카나리 객체** — Juice Shop에 실사용 없는 상품·주문 ID를 정해 두고 그 ID 접근을 Wazuh 룰로 경보 | 룰 1개 + 대상 ID 목록 | BOLA 열거에 대한 **고정밀 탐지 기준선** → ML과 비교 | `08` §2-5, `07` §6 비교군 |
| 3 | **위험 점수 누적** — IP별 (Wazuh 저레벨 알럿 가중합 + ML 이상 점수) | 피처 표 재사용 | 느린 공격 보완, SOAR 판단 단계 입력 | `04` 판단, `10` §3 |
| 4 | 동료 집단 비교 · 시퀀스 분석 | 큼 | 탐지 폭 확장 | 시간 남으면 |

**주의**
- 카나리 객체는 정상 사용자 스크립트가 **절대 접근하지 않도록** 목록에서 제외해야 기준이 오염되지 않는다
- 위험 점수 가중치는 정상 수집 기간 데이터로 정하고, 공격 기간 데이터로 조정하지 않는다 (채점 데이터로 튜닝 금지)
