# 36. 실제 사람 정상 트래픽 수집과 평가 계획

> 날짜: 2026-11-12 · 관련: `docs/35`(재생 정상 실험 — 평가 정상이 생성기 출신인 한계) · 도구: `human_collect/`
> 상태: **도구 준비 완료, 수집 전.** 수집·판단·해석은 사용자가 직접 한다.

## 0. 왜

docs/35 §3-6: 재생 정상을 40명 넣을 때 생성기 출발지 오탐이 가장 낮고(AE 5.7%), 70·100명이면 다시 오른다.
하지만 평가 정상이 **생성기 출신**이라, 이 최적값이 '생성기에 맞춘 값'인지 '사람에게도 맞는 값'인지 모른다.
→ 실제 사람 정상으로 평가해야 판정된다.

## 1. 수집 설계

| 항목 | 정한 것 | 이유 |
|---|---|---|
| 인원 | 8~10명 이상, 가능하면 2회(다른 날) | 사람 1명 = 출발지 1개. 재방문 패턴도 필요 |
| 시간 | 1회 20~30분 | 5분 창 4~6개 이상 |
| 지시 | 목표만("선물 하나 골라 보기"), 방법은 자유 · 그냥 나가도 됨 | 자세히 지시하면 사람이 생성기처럼 움직인다 |
| 식별 | nginx 기본 인증 아이디(p01 …) | 같은 와이파이·터널 뒤에서도 사람 구분, **실제 IP 미기록** |
| 서버 | Juice Shop `sha256:877fc77b…`(재생 실험과 동일) + nginx | 버전이 다르면 경로·응답이 달라 비교 불가 |
| 공개 | Cloudflare 임시 터널, 수집 중에만 | Juice Shop 은 의도적으로 취약 — 기본 인증 뒤, 기간 한정 |
| 동의 | 안내문에 기록 항목·삭제 요청 명시 | 브라우저 정보·행동 기록이 남는다 |

변환: `tools/human_log_to_combined.py` — pNN → 가상 IP `10.40.0.NN`, 기본 인증 실패(앱까지 안 간 요청, upstream `-`)는 제외, 앱의 로그인 실패 401 은 유지.
로컬 확인(2026-11-12): 인증 통과 요청만 남고, 앱 401 유지, 기본 인증 실패 2줄 제외 → `features.py` 까지 통과.

## 2. 평가 (수집 후)

실제 사람(`10.40.*`)은 **평가 전용**(`--test-only-prefix 10.40.`) — 학습에 절대 넣지 않는다.

| 조건 | 학습 정상 | 볼 것 |
|---|---|---|
| A | 생성기만 | 사람 오탐률 |
| B40 / B70 / B100 | 생성기 + 재생 40·70·100명 (같은 사람 목록, docs/35 §3-6) | 사람 오탐률이 A 보다 낮은가, 몇 명에서 가장 낮은가 |

- 공격 탐지율은 docs/35 와 같은 방식으로 함께 본다(오탐만 낮추고 탐지를 잃으면 의미 없음).
- 판정 질문:
  1. 생성기만 배운 모델이 실제 사람을 얼마나 오탐하나? (docs/35 C 의 재생 오탐 14~42% 와 비슷한가)
  2. 재생을 넣으면 **실제 사람** 오탐이 줄어드나?
  3. 사람 기준 최적 재생 인원이 40명(생성기 기준 최적)과 같은가?
- 주의: 참가자가 '실험 중'임을 알아 평소와 다르게 행동할 수 있다. 참가자 수가 적으면 한 명의 영향이 크다(사람 단위로 결과를 같이 볼 것).

## 3. 역할

- 도구 준비·검증: 완료(이 문서, `human_collect/`).
- **사용자**: 참가자 모집 · 서버 켜고 끄기 · 기록표 · 위 판정 질문에 대한 결론과 해석 작성(docs/36 §4 로 추가).
