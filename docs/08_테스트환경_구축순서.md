# 08. 테스트 환경 구축 순서 (쇼핑몰 타겟 + Wazuh + ML)

> 작성일: 2026-10-22 · 상태: 계획(초안)
> 목표: 쇼핑몰 타겟 서버에서 **정상·공격 로그**를 발생시키고, Wazuh로 수집해 **ML 이상 탐지**의 입력(alerts.json + archives.json)을 만든다.
> 전제: 기존 Home SOC Lab(VMware + Rocky 9 + Docker Wazuh 4.9.0 + ELK, Kali) 재사용.
> 역할: 환경 구축은 환경 팀, ML·LLM 분석은 분석 담당.

---

## 0. 전체 구조

```
[타겟 VM] Rocky/Ubuntu
  - OWASP Juice Shop (쇼핑몰 웹앱, Docker)
  - 웹서버 접근 로그 (nginx 또는 앱 로그)
  - SSH 서비스
  - Wazuh 에이전트
       │ (로그 수집)
       ▼
[Wazuh 매니저] (기존 Home SOC Lab)
  - 룰 분석 → alerts.json (룰에 걸린 것)
  - logall_json → archives.json (전체 로그)
       │
       ▼
[ML/LLM] 분석 담당 (alerts.json + archives.json 입력)

[Kali] ── 공격 ──▶ 타겟 VM
```

## 1. 왜 이 구조인가 (논의 결과)

- **ML을 쓰는 이유**: 룰(Wazuh)은 "아는 공격"만 잡는다. 느린 공격·BOLA·새로운 공격은 룰이 침묵 → ML이 "평소와 다른 행동"으로 보완
- **alerts vs archives 둘 다 쓰는 이유**: alerts.json은 룰이 거른 것만 → ML이 "룰이 놓친 것"을 보려면 전체(archives.json)가 필요. 둘을 비교하는 것이 실험
- **정상 로그는 우리 랩에서**: 비지도 학습의 "정상 기준"은 우리 환경 로그로 세워야 한다(공공데이터로 대체 불가). 이상 데이터는 소량(채점용)이면 충분
- **공공데이터(CSIC) 섞기 제외**: 비지도 학습엔 정상 기준만 있으면 되므로 데이터 합성이 불필요

## 8. nginx 단독 구축 (Wazuh 없이) — 2026-10-23 추가

> 배경: Wazuh VM(newwazuh)은 OS는 켜지지만 Wazuh 서비스 포트(443·1514·1515·9200·55000)가 모두 닫힌 상태(2026-10-23 확인, 호스트 RAM 16GB 중 여유 2.7GB — 메모리 부족 의심).
> 결정: ML은 **nginx 접근 로그를 직접** 읽고(`ml/features.py --nginx`), 룰 비교는 파이썬 룰 비교군(`ml/models.py --methods rule`)으로 대신한다. Wazuh는 살아나면 alerts vs archives 비교만 추가.

### 8-0. 먼저 정할 것

| 항목 | 권장 | 이유 |
|---|---|---|
| 타겟 VM | Rocky Linux 9 최소 설치, vCPU 2, RAM 2~3GB, 디스크 20GB | Juice Shop + nginx만이라 가벼움 |
| Wazuh VM | 실험 중 끄거나 RAM 6GB로 축소 | 호스트 메모리 확보 |
| **네트워크** | 타겟은 **호스트 전용(Host-only) 또는 NAT** | Juice Shop은 의도적 취약 앱 → 브리지(공유기 대역)에 열지 않는다 |

시작 전에 VMware **스냅샷**을 떠 둔다 (꼬이면 되돌리기).

### 8-1. Docker 설치

```bash
sudo dnf -y install dnf-plugins-core
sudo dnf config-manager --add-repo https://download.docker.com/linux/rhel/docker-ce.repo
sudo dnf -y install docker-ce docker-ce-cli containerd.io docker-compose-plugin
sudo systemctl enable --now docker
sudo docker run --rm hello-world        # 완료 기준: Hello from Docker!
```

### 8-2. Juice Shop (127.0.0.1에만 공개 — 외부엔 nginx만)

```bash
sudo docker run -d --name juice-shop --restart unless-stopped \
  -p 127.0.0.1:3000:3000 bkimminich/juice-shop
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:3000/   # 완료 기준: 200
```

### 8-3. nginx 리버스 프록시 + 접근 로그

```bash
sudo dnf -y install nginx
sudo tee /etc/nginx/conf.d/juiceshop.conf >/dev/null <<'CONF'
server {
    listen 80;
    server_name _;
    access_log /var/log/nginx/juiceshop_access.log combined;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header Upgrade $http_upgrade;     # Juice Shop은 웹소켓 사용
        proxy_set_header Connection "upgrade";
    }
}
CONF
```

- Rocky 기본 `/etc/nginx/nginx.conf`의 `server { listen 80 … }` 블록은 **주석 처리** (80번 충돌)

```bash
sudo setsebool -P httpd_can_network_connect 1     # SELinux: nginx → 3000 연결 허용
sudo firewall-cmd --permanent --add-service=http && sudo firewall-cmd --reload
sudo nginx -t && sudo systemctl enable --now nginx
```

완료 기준: 호스트 브라우저에서 `http://<타겟IP>/` 접속 → Juice Shop 화면, `sudo tail -f /var/log/nginx/juiceshop_access.log`에 클릭마다 줄이 쌓임

### 8-4. 시간 동기화

```bash
sudo systemctl enable --now chronyd
timedatectl          # "System clock synchronized: yes"
```

nginx 로그엔 시간대(`+0900`)가 함께 찍히고 분석 코드는 UTC로 변환한다. **정답지와 `--train-until`은 UTC로** 적는다.

### 8-5. 정상 트래픽 (§3 보완)

- 팀원이 **서로 다른 기기**(호스트 PC 브라우저, 다른 VM 브라우저 등)로 평소처럼 둘러보기·검색·로그인·**자기 장바구니** 사용 → 기기가 다르면 IP도 다름
- 반복이 필요하면 Playwright의 `playwright codegen <주소>`로 평소 흐름을 녹화해 여러 VM에서 대기 시간을 두고 재실행
- 이 기간엔 공격 금지, **정상 기간 끝 시각(UTC)** 기록 → `ml/models.py --train-until`

### 8-6. 첫 연결 확인 (분석 PC)

```bash
# 타겟: 로그를 홈으로 복사 (원본은 root 권한)
sudo cp /var/log/nginx/juiceshop_access.log* ~/ && sudo chown $USER ~/juiceshop_access.log*

# 분석 PC
scp <계정>@<타겟IP>:~/juiceshop_access.log* data/
python ml/features.py --nginx data/juiceshop_access.log --out data/features_web.csv
```

완료 기준: `nginx 요청 N줄 사용`, "형식이 다른 줄" 0개. 0이 아니면 그 줄을 분석 담당에게 전달해 파서를 맞춘다.

### 8-7. 실험 중 주의

- **로그 로테이션**: 매일 `….log.1`, `….log.2.gz`로 넘어간다. `features.py`는 여러 파일·`.gz`를 그대로 읽으므로 끝날 때 전부 가져온다 (오래된 것부터 `--nginx`를 여러 번)
- **사용자마다 다른 IP**: 호스트 전용 네트워크는 호스트와 VM끼리만 접속 가능 → 기기를 나눠 접속. 팀원 기기가 필요하면 브리지로 하되 **방화벽에서 팀원 IP만 허용**
- 분석 순서는 `ml/README.md`의 "Wazuh 없이" 명령 (`features.py --nginx` → `models.py --train-until` → `evaluate.py` → `explain_llm.py`), 지도/비지도 비교는 `docs/12`
