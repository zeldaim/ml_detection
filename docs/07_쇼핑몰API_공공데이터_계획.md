## 1. 왜 쇼핑몰 API인가

- **공공데이터가 있다** — CSIC 2010은 쇼핑몰 웹 애플리케이션 트래픽으로, 정상·공격에 정답이 붙어 있다
- **기존 작업과 바로 이어진다** — 신한 사고(API 대입·BOLA) 제안서, API 대입공격 런북, 랩 01 구조, Shadow API 계획
- **OWASP API Top 10 직접 대응** — API1 BOLA, API2 인증 실패, API4 무제한 리소스 소비, API6 민감 비즈니스 흐름 남용

## 2. 데이터 소스

> 이용 조건·라이선스·현재 공개 여부는 받기 전에 각 출처에서 확인. 원본 재배포가 금지된 경우 저장소엔 다운로드 방법만 적는다.

| 데이터 | 내용 | 확인 상태 | 용도 |
|---|---|---|---|
| **CSIC 2010 HTTP** | 쇼핑몰(장바구니·회원가입) 대상 HTTP 요청. 정상 약 36,000건, 공격 25,000건 이상, 정답 표시. 공격 유형: SQLi, XSS, 버퍼 오버플로, 정보 수집, 파일 노출, CRLF, SSI, 파라미터 변조 | 공식 페이지 확인 | **메인**: 정상 기준 + 페이로드 공격 |
| Kaggle API Access Behaviour Anomaly | API 접근 행위 이상 데이터 | 2차 출처로만 확인 — **열·정답 정의 확인 필요** | 행위 피처 참고·보조 |
| LO2 (마이크로서비스 API 로그·지표) | 마이크로서비스 API 로그와 지표 | 논문 확인 | 정상 패턴·지표 참고 (이상은 장애 위주, 공격 아님) |
| 실제 온라인 쇼핑몰 접속 로그 | 2020년 논문에서 공개된 것으로 보이는 쇼핑몰 서버 로그 | **저장소 미확인** | 확인되면 현실적 정상 배경 |

**CSIC 2010의 한계 (보고서에 명시)**
- 단일 도메인·단일 컴퓨터에서 생성 → 사용자·IP 다양성이 거의 없음
- 오래된 데이터, 생성 방법이 정확히 공개되지 않아 갱신 불가
- 공격이 **요청 문자열** 수준 → **BOLA 같은 행위 공격은 없음**

→ 그래서 **IP·사용자·시간은 우리가 다시 입히고**, 행위 공격은 직접 만든다.

## 3. 데이터 구성 — 공공 + 직접 생성 합치기

```
CSIC 2010 정상 ──┐
                 ├─▶ [재생기] 가상 사용자·IP·시각을 입혀 하나의 접속 로그로 ──▶ access.log + answer.csv
CSIC 2010 공격 ──┤      (정상 사용자 N명이 세션 단위로 장바구니·조회·주문)
                 │
직접 생성 행위 공격 ┘   BOLA 대입(빠른·느린), 크리덴셜 스터핑, 대량 수집
```

### 3-1. 재생기(replayer)가 하는 일
1. CSIC 요청을 **가상 사용자 세션**으로 묶는다 (사용자마다 IP·토큰·접속 시간대 부여)
2. 세션 안의 요청 간격을 사람처럼 불규칙하게 둔다
3. 공격 요청은 **공격자 세션**에 배정하고 정답지에 기록
4. 모든 요청을 **같은 로그 형식**(예: nginx combined + 사용자 ID·응답코드·응답크기)으로 출력

### 3-2. 출처 함정 막기 (`05` §1)
- 공공 요청과 직접 만든 공격 모두 **같은 재생기·같은 로그 형식**을 거친다
- 공격자만 특이한 IP 대역·시간대·User-Agent를 쓰지 않는다
- 검증: **IP·시간대 피처를 뺀 모델**로도 탐지되는지 확인

## 4. 공격 시나리오

| # | 유형 | 출처 | 핵심 신호 | 룰로 잡히나 |
|---|---|---|---|---|
| A1 | SQLi·XSS 등 페이로드 | CSIC 2010 | 요청 문자열의 특수문자·키워드 | 시그니처로 대부분 ✅ |
| A2 | 파라미터 변조 | CSIC 2010 | 값의 범위·형식 이상 | 일부 |
| **B1** | **BOLA 대입 — 빠른** (주문번호·고객번호 연속 조회) | 직접 생성 | 짧은 시간 **서로 다른 객체 ID 다수**, 403/404 비율 | 레이트리밋 룰 ✅ |
| **B2** | **BOLA 대입 — 느린** (분산·저속) | 직접 생성 | 장시간 객체 ID 다양성 누적, 간격 규칙성 | **❌ (ML 필요)** |
| B3 | 크리덴셜 스터핑 | 직접 생성 | 로그인 실패 다수, 계정 다양성 | 일부 |
| B4 | 상품·가격 대량 수집(스크래핑) | 직접 생성 | 조회만 하고 장바구니·주문 없음, 순차 접근 | ❌ |

**정상인데 헷갈리는 것도 넣는다**: 장바구니에 많이 담는 사용자, 세일 시간대 몰림, 주문내역 여러 건 조회 → 오탐 측정용

**B1·B2 생성 방법**: finance_secure `런북/API대입공격_실습`의 공격 재현 코드 재사용, 또는 OWASP Juice Shop(취약 쇼핑몰, Docker 1줄) — **우리가 통제하는 랩에서만**

## 5. 탐지 — 2층 구조

| 층 | 단위 | 질문 | 방법 | 피처 예시 |
|---|---|---|---|---|
| **요청 층** | 요청 1건 | 이 요청이 악성인가? | 룰(시그니처) / 분류기 / LLM | 길이, 특수문자 비율, 키워드, 파라미터 엔트로피 |
| **행위 층** | 사용자(IP·토큰) × 5분 | 이 사용자의 행동이 이상한가? | **Isolation Forest** (랩 01 방식) | 요청 수, **서로 다른 객체 ID 수**, 에러 비율, 간격 변동계수, 조회/주문 비율, 엔드포인트 엔트로피 |

- **요청 층은 A계열**(페이로드)을, **행위 층은 B계열**(BOLA·스크래핑)을 주로 잡는다 → 두 층이 왜 다 필요한지가 결론
- 엔트로피 피처는 기존 Phase 4 코드(`06` §4) 재사용

## 6. 비교군과 채점 (`03` 확장)

| # | 방식 | 대상 |
|---|---|---|
| ① | 룰: 시그니처(페이로드) + 레이트리밋(N초 M회) | WAF·API 게이트웨이 수준의 기존 방어 |
| ② | ML: 행위 층 Isolation Forest | B계열 |
| ③ | LLM: 요청·사용자 요약 판단 + 설명 | A·B 전체 |
| ④ | ① + ② + ③ 조합 | 실전형 |

채점: 탐지율 · 오탐률(헷갈리는 정상 포함) · 탐지 시간 · 비용 · 설명력 — **정답지 기준**

**예상 결론**: 룰은 A계열·B1에 강하고 **B2·B4에 침묵**, ML은 B2·B4를 잡지만 이유 설명이 약함, LLM이 설명을 보완 → 조합이 실용적

## 7. 확장 — 항공사 챗봇을 통한 예약조회 BOLA

**시나리오**: 항공사 상담 챗봇이 내부적으로 **"예약번호로 예약 조회" API**를 호출한다. 공격자가 챗봇에게 예약번호를 바꿔가며 물어보게 해 남의 예약 정보를 얻는다 = **챗봇을 통한 BOLA**.

| 구성 | 데이터 | 확인 상태 |
|---|---|---|
| 정상 질문 | **ATIS** (항공 예약·여행 질문 데이터) | 널리 쓰이는 공개 데이터 — 이용 조건 확인 |
| 인젝션 질문 | **deepset/prompt-injections** (662문장, 정상/인젝션 표시, Apache-2.0) | Hugging Face 확인 |
| 예약번호 대입 | 직접 생성 — 세션 안에서 예약번호만 바꾼 질문 반복 | — |

**탐지**
- 메시지 층: 인젝션 문장 판별 (분류기·LLM)
- 세션 층: 세션당 **서로 다른 예약번호 수**, 조회 실패 비율 → **쇼핑몰 행위 층과 같은 피처·같은 모델** 재사용
- 메시지: "입구가 챗봇이어도 결국 뒤의 API를 지켜야 한다"

**동기 사례**: Air Canada 챗봇 사건(2024, 챗봇의 잘못된 안내에 항공사 책임 인정) — 챗봇 응답 신뢰 문제. 공격 사례는 아니므로 "챗봇 위험의 현실성" 근거로만 사용.

## 9. 주의

- 의도적 취약 앱(Juice Shop 등)과 공격 생성은 **우리가 통제하는 랩에서만**
- 공공데이터는 각 이용 조건 준수, 큰 원본은 Git에 올리지 않음(`data/`는 `.gitignore`)
- CSIC 2010의 한계(§2)와 "IP·시간은 우리가 입혔다"는 점을 보고서에 **명시** — 결과를 실제 운영 환경 성능으로 과장하지 않는다
- LLM에 보내는 데이터는 공공·모의 데이터만, 요청 원문을 보낼 때는 로그 조작 위험(랩 01 4단계) 고려
