# 20. API 보안을 위한 데이터셋 설계 (플라이휠의 설계 바퀴)

> 작성일: 2026-10-24 · 상태: 설계(v2 스펙)
> 목적: OWASP API Top 10 을 **행위 기반 ML**로 탐지하기 위한 **가장 좋은 데이터셋의 설계도**를 못 박는다.
> 이건 "데이터를 다 모은 것"이 아니라 **무엇을·어떻게 모으고 라벨·피처를 어떻게 둘지**의 스펙이다.
> 플라이휠은 이 스펙대로 **실제 로그를 채우고 검증**하며 돈다. (원리: `docs/19`)

## 0. 한 문장

> **행위로 보이는 공격(열거·대입·수집)은 피처로 잡고, 내용으로만 보이는 공격(위조·주입)은 대조군으로 둔다.
> 라벨은 공격을 통제해 '사실'로 기록하고, 피처는 가설로 넣되 교차검증으로만 남긴다.
> 스키마를 고정하고 버전을 매겨, 합성으로 넓이를 보강하되 검증은 실제 로그로 한다.**

## 1. 범위 — OWASP API Top 10 을 두 축으로 나눈다

우리 피처는 **로그에 남는 행위**를 본다. 그래서 공격을 "행위로 드러나나"로 가른다.

| 축 | OWASP API 항목 | 로그 신호 | ML(행위) | 데이터셋 역할 |
|---|---|---|---|---|
| **행위형** | API1 BOLA(객체 열거) | 남의 객체 ID 다수·연속 | ✅ 기대 | **양성 핵심** |
| | API2 Broken Auth(대입) | 로그인/OTP 반복, 401 급증 | ✅ 기대 | **양성 핵심** |
| | API3 과다수집 / API4 자원고갈 | 고속·대량 요청 | ✅ 기대 | 양성(공개자원은 애매→대조) |
| | API10 부적절한 재고관리 | 구버전 경로 스캔 | △ | 보조 |
| **내용/단발형** | API5 BFLA(관리자 1회 호출) | 단발, 행위 안 튐 | ❌ 어려움 | **대조군** |
| | API6 Mass Assignment / API8 설정오류 | 페이로드 내용 | ❌ | 대조군(내용축은 `load_csic`) |
| | API7 SSRF / JWT 위조 | 단발·내용 | ❌ | 대조군 |

> 결론 지향: **"행위 피처로 잡히는 것 / 안 잡히는 것"의 경계표**를 데이터셋으로 증명하는 게 목표다.
> 이는 `docs/13`의 "2층 구조(발견=비지도, 분류=지도)"와 CSIC "내용 공격 ≠ 행위 공격"(`docs/16`)의 API 버전이다.

## 2. 어떤 로그를 모으나 (수집 소스)

| 소스 | 뽑는 것 | 비고 |
|---|---|---|
| API GW / nginx access | 출발지, 시각, 메서드, **경로 템플릿**, 상태코드, 응답바이트 | crapi-web/Juice Shop 모두 가능. UUID 경로는 `features.py`가 `{id}`로 정규화(완료) |
| 인증 이벤트 | 로그인 성공/실패, OTP 시도 | 대입/Broken Auth 신호 |
| (선택) Wazuh archives.json | 정상 포함 전체 이벤트 | 정상 대표성 확보 (`logall_json=yes`) |
| (선택) JWT `sub` | 로그인 후 출발지 귀속 | **원문은 피처 금지**(누수), 라벨 키로만 |

> **출발지 키**: 기본 IP, 가능하면 계정/JWT `sub` 병행. **IP·계정·UA·pod 이름은 피처로 넣지 않는다**(라벨 누수).

## 4. 라벨 스키마 (정답지)

라벨은 **사실 기록**이다(LLM 대행 불가, `docs/19` §7). 공격 러너가 남긴 근거로 붙인다.

| 열 | 뜻 | 예 |
|---|---|---|
| `src` | 출발지(공격 pod/IP, 가능하면 계정) | `10.16.1.213` |
| `start`,`end` | 공격 시작·끝 **UTC**(초 단위) | `2026-...T08:19:31Z` |
| `type` | 공격 종류 | `bola`, `brute`, `harvest` |
| `subtype` | 변주 | `bola_slow`, `brute_fast` |
| `owasp` | 매핑 | `API1`, `API2` |

- 라벨 규칙: **출발지 AND 시각** 교집합만 그 종류, 그 외 `normal`(공격 중 정상 트래픽 보존). `accumulate.py`가 수행.
- **최고 정밀도 옵션**: 공격 요청에 **표식 헤더/UA**를 달아 요청 단위로 라벨 → 그 표식은 **피처에서 제외**(누수 방지).

## 5. 데이터셋 구성 원칙 (좋은 데이터셋의 조건)

1. **정상 대표성**: 여러 사용자·여러 시간대·여러 동선. 단조로운 정상은 "완벽한 점수" 함정(`docs/17`).
2. **변주 > 양**: 공격은 **빠른/느린 두 버전** 이상, 여러 종류. 한 도구·한 패턴만 쌓으면 과적합(`docs/19` §2-1).
3. **실제 검증셋 분리(held-out)**: 합성으로 학습 넓이를 보강해도 **검증은 실제 로그 별도 보관분**으로. (합성→합성 금지)
4. **균형 관리**: 정상:공격 비율과 종류별 수를 `accumulate.py --stats`로 추적. 과도한 불균형은 지표 왜곡.
5. **출처 추적**: `source`(합성/실제·날짜), `scenario`로 provenance. 디버깅·분할·누수추적에 필수.
6. **스키마 고정·버전**: 열 순서·이름 불변. 피처 추가는 버전업+재생성.

## 7. 누적 파일 & 플라이휠 연동

- 현재: `data/dataset_web.csv` (v1, 합성 44행 — 첫 삽 완료).
- v2 채택 시: `data/dataset_api_v2.csv` 로 새로 쌓기(스키마 분리).
- 한 바퀴:
  1. 시나리오 실행(변주 포함) → 시각/출발지/표식 기록 → `answer.csv`
  2. `features.py` → `accumulate.py --source <실제_날짜>` 로 append
  3. `supervised.py`(처음보는 공격)·`models.py`+`evaluate.py`로 검증 → 피처/파라미터 조정
  4. `train_export.py` 재학습·저장, `predict.py`로 다음 수집 때 바로 탐지
  5. `accumulate.py --stats` 로 균형·출처 점검 → 부족한 변주/종류 보강

## 8. 지금 당장 할 수 있는 것 (crAPI 없이)

기존 Juice Shop도 `/rest/...`·`/api/...` API 경로가 있어 **행위형 API 공격 데이터는 지금 랩으로 시작 가능**.
