# 09. 설계 논의 히스토리 (2026-10-22)

> ML·LLM 기반 로그 이상 탐지 프로젝트의 방향을 잡기 위한 질의응답 기록.
> 결론만 보지 말고, **왜 그렇게 정했는지**를 남긴다. 중간에 바뀐 판단과 그 이유도 포함.

---

## Q1. 엔트로피 랩 데이터를 실제 ML에 쓸 수 있나?
- 데이터(`entropy_log.jsonl`)는 34분·공격 93%·에이전트 1개 → **본 학습 데이터로는 부적합**
- 공격이 다수라 Isolation Forest가 공격을 "정상"으로 학습할 위험
- **쓸 수 있는 것**: 엔트로피 계산 코드(재사용), 개념 증명(동기 그림)
- 결정: 데이터는 파일럿, **코드는 재사용** (→ `06` v2)

## Q2. 공공데이터로 부족한 데이터를 채울 수 있나? (쇼핑몰 API / 항공 챗봇)
- 쇼핑몰: **CSIC 2010**(정상·공격 라벨 있음)이 맞음
- 챗봇: 문장 데이터만 있고 로그가 없음 → "챗봇을 통한 BOLA"로 확장
- 결정: 쇼핑몰 메인 + 챗봇 확장 (→ `07`). 이후 ML 방식 논의로 방향 전환

## Q3. CSIC 라벨은 "학습된" 것인가?
- 아니다. **사람이 파일로 나눠 표시**한 것(normal 파일 / anomalous 파일)
- 학습된 모델이 아니라 **정답이 붙은 데이터**
- 어느 파일에서 왔는지만 보면 정답이 자동으로 정해짐

## Q4. 지도학습 vs 비지도학습 vs LLM — 데이터 부족과의 관계
- **지도학습**: 정상+공격 라벨 다 필요 → 공격 적으면 타격 큼
- **비지도학습(Isolation Forest)**: **정상만** 있으면 됨 → 공격 소량 OK
- **LLM**: 학습 안 함. 일반 지식으로 그때그때 판단
- 결정: **비지도 + LLM** 조합이 데이터 부족 상황에 맞음

## Q5. 비지도학습은 정답으로 학습해서 라벨을 만드나?
- **아니다.** 비지도학습은 **정답을 보지 않고** 학습 (정답 보면 지도학습)
- 판단 방식은 엔트로피가 아니라 **"고립시키기"**(엔트로피는 피처 하나)
- 라벨을 만드는 게 아니라 **점수**를 매김 → 이상/정상 판정은 사람이
- LLM과 다름: ML은 우리 데이터의 평소 기준, LLM은 세상 지식

## Q6. 왜 채점표(정답)가 필요한가?
- **실제 운영**: 채점표 불필요 (ML이 혼자 판단)
- **프로젝트(지금)**: "우리 탐지기가 잘 맞히나"를 증명해야 함 → 정답 필요
- 비유: 면허 시험(채점) vs 실제 운전(혼자)

## Q7. 정상 기준을 공공데이터로 세워도 되나?
- **안 된다.** CSIC는 스페인 쇼핑몰(2010) → 우리 환경과 경로·사용자·시간대가 다름
- 공공데이터로 기준 세우면 **우리 정상 로그도 통째로 "이상"**으로 나옴
- 정상 기준 = **우리 랩 정상 로그**로 세워야 함

## Q8. 기준만 세우면 이상 데이터는 1개여도 되나?
- **맞다.** 이게 비지도학습의 핵심
- 정상 기준이 서면, 이상 로그는 소량이어도 "벗어났나" 판단 가능
- → **공격 데이터를 많이 만들 필요 없음** → 데이터 합성 불필요

## Q9. 공공데이터에 우리 데이터를 끼워넣는 작업은 왜 하자고 했나?
- 처음 계획(`05`,`07`)에선 "채점용 데이터"를 만들려던 것
- 그러나 (1) 그 합성 작업이 **안전 제약에 막힘**, (2) 비지도학습엔 **애초에 불필요**
- 결정: **데이터 합성 제외.** CSIC와 랩 로그를 따로 사용

## Q10. ML은 "이상"만 찾고 악성 판단은 안 하는 것 아닌가?
- **맞다.** Isolation Forest = 이상 탐지(평소와 다름). 악성 여부는 판단 안 함
- 악성 판단은 LLM 또는 사람의 몫
- 따라서 "요청 층(악성 문자열 판단)"은 ML 이상탐지에 **필수가 아님**
- 본인 목표(행동 이상 탐지)엔 **우리 랩 정상 로그만** 있으면 됨

## Q11. Wazuh가 이미 알럿·위험도를 주는데 왜 ML인가?
- Wazuh(룰)는 **사람이 적은 규칙**만 잡음 → 느린/새로운/정상 같은 공격(BOLA)에 침묵
- ML은 규칙이 아니라 **행동 패턴**을 봄 → 룰이 놓친 것 보완
- 개별 저레벨 알럿을 **묶어서** 봄
- 메시지: **"룰은 침묵, ML은 탐지"**

## Q12. 전체 로그 분석 vs Wazuh 로그 분석은 다른가?
- **다르다.**
  - `alerts.json`: 룰에 걸린 것만 → ML이 "룰이 놓친 것"을 보기 어려움
  - `archives.json`: 전체 로그 → ML이 룰 밖의 이상도 볼 수 있음
- 결정: **둘 다 넣고 비교**. "원본을 넣으면 더 잡는다"가 ML 가치의 근거

## Q13. ML이 원래 이렇게 간단한가? 직접 모델을 만들어야 하나?
- 모델 코드는 **원래 몇 줄**. 실무 차이는 피처·데이터 정제·평가·운영에 있음
- 모델은 다양: Isolation Forest, LOF, One-Class SVM, Autoencoder …
- **직접 안 만듦.** scikit-learn 갖다 씀. 본인은 **피처·결과 해석**에 집중
