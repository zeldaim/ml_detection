  - 상태: 200 2,157 · 201 14 · 400 3 (`POST /api/BasketItems` — Juice Shop 상품별 수량 제한, 서버의 실제 응답이라 그대로 둠)

- 비교 (모두 `--group-by type --contamination 0.05`, 출발지 분할 seed 0~4, **평가 정상 출발지는 A·B 동일**):
  - **A 기준선**: 생성기 정상만 학습 (`--exclude-prefix 10.30.`)
  - **B 재생 추가**: 재생 40명을 학습 전용으로 더함 (`--train-only-prefix 10.30.`)
  - **C 불일치 측정**: 생성기 정상 전부로 학습 → 재생 정상 205구간에 오탐이 얼마나 나나

## 2. 고친 것: LOF 와 중복 행

재생 데이터는 **완전히 같은 피처 행이 44번** 나온다(방문 = 페이지 로드 + 상품 1개 = 7요청. 로그가 초 단위라 간격 패턴까지 같아짐).
LOF 는 같은 점이 이웃 수(20)보다 많으면 밀도가 무한대가 되어 판정이 깨진다 → 첫 실행에서 B 의 LOF 탐지가 **0/32**(고장).
→ `supervised.py` 의 LOF 학습을 **고유 행만** 쓰도록 변경. 생성기 데이터(최대 중복 5)에도 적용되어 **A 의 LOF 수치가 docs/33 과 조금 다르다**
(docs/33 §5-1: 탐지 141/160 · 오탐 12% → 이번 A: 145/160 · 10.1%).

## 3. 결과

### 3-1. 지름길 없음 — 재생 정상은 생성기 정상과 피처 하나로 갈리지 않는다

정상끼리(재생 205 vs 생성기 214) 단일 피처 AUC 최대 `interval_cv` 0.833, 나머지 0.51~0.75. 0.99 이상 없음.

### 3-2. C — 생성기로만 학습하면 사람 같은 정상을 많이 오탐한다

| 모델 | 재생 정상 오탐 구간 | 한 번이라도 걸린 재생 출발지 |
|---|---|---|
| IF | 29/205 (14%) | 17/40 |
| LOF | 54/205 (26%) | 21/40 |
| AE | 50/205 (24%) | **35/40** |

학습 정상(생성기)의 5% 를 이상으로 두는 설정인데, OTTO 행동을 재생한 정상에선 14~26%. 생성기 정상이 '사람 같은 행동'을 덮지 못한다는 직접 근거.

### 3-3. A vs B — 재생 정상을 학습에 넣으면 (seed 0~4 합)

| 모델 | A 탐지 | B 탐지 | A 오탐 | B 오탐 |
|---|---|---|---|---|
| IF | 69/160 (43%) | **114/160 (71%)** | 5.2% | 5.7% |
| LOF | 145/160 (91%) | 139/160 (87%) | 10.1% | 9.0% |
| AE | 139/160 (87%) | **151/160 (94%)** | 9.0% | **5.7%** |
| IF\|LOF\|AE | 147/160 (92%) | 152/160 (95%) | 15.0% | **11.7%** |
| RF | 100/160 (62%) | 63/160 (39%) | 5.4% | 3.0% |

- **AE: 탐지 87→94%, 오탐 9.0→5.7%** — 둘 다 좋아짐. IF 는 탐지 43→71%(오탐 비슷). LOF 는 큰 차이 없음.
- 시드별 편차는 여전히 크다(예: B 의 AE 오탐 0%~14%, seed 2 가 가장 나쁨) — 평균만 보고 결론 내지 말 것.
- RF 는 탐지가 떨어짐(62→39%): 재생 정상이 '정상' 라벨로 들어가며 결정 경계가 바뀜. 처음 보는 종류 평가에서 RF 는 원래 불안정(docs/33 §5-2).

### 3-4. 다른 40명으로 재현 (재생 시드 1, `docs/35_결과/run_output_s1.txt`)

`replay_clickstream.py --users 40 --seed 1` → `data/otto_replay_s1.log` (2,606줄, 200 2,563 · 201 37 · 400 6) → 재생 252구간.
기준선 A 는 재생 데이터를 안 쓰므로 두 실행에서 같은 값(스크립트로 일치 확인).

| 모델 | A 탐지 | B 탐지 s0 / s1 | A 오탐 | B 오탐 s0 / s1 |
|---|---|---|---|---|
| IF | 43% | 71% / 68% | 5.2% | 5.7% / 4.9% |
| LOF | 91% | 87% / 86% | 10.1% | 9.0% / 6.8% |
| AE | 87% | **94% / 95%** | 9.0% | **5.7% / 6.3%** |
| IF\|LOF\|AE | 92% | 95% / 96% | 15.0% | 11.7% / 9.8% |
| RF | 62% | 39% / 39% | 5.4% | 3.0% / 2.9% |

- C(생성기만 학습 → 재생 정상 오탐): s0 IF 14% · LOF 26% · AE 24% → s1 IF 19% · LOF 32% · AE 19%. 같은 방향.
- 지름길: s1 도 단일 피처 AUC 최대 `interval_cv` 0.839.
- **방향은 재현됐다**: AE·IF 탐지↑, AE·LOF·앙상블 오탐↓, RF 탐지↓. 크기는 재생 구성에 따라 ±1~2%p.
- 평가 출발지 seed 2 는 두 경우 모두 오탐 13~20% 로 가장 나쁨 — 특정 생성기 출발지 조합(101·105·106·112)이 다른 정상과 다르게 보이는 것. 재생으로도 안 줄어드는 부분.

### 3-5. 인원 100명 (재생 시드 2, `docs/35_결과/run_output_s2_n100.txt`)

`--users 100 --seed 2` → `data/otto_replay_s2_n100.log` (5,938줄, 200 5,859 · 201 53 · 400 26) → 재생 568구간(생성기 정상 214구간의 2.7배).

| 모델 | A 탐지 | B 탐지 40(s0) / 40(s1) / **100** | A 오탐 | B 오탐 40(s0) / 40(s1) / **100** |
|---|---|---|---|---|
| IF | 43% | 71% / 68% / **82%** | 5.2% | 5.7% / 4.9% / 5.4% |
| LOF | 91% | 87% / 86% / 88% | 10.1% | 9.0% / 6.8% / 9.0% |
| AE | 87% | 94% / 95% / 95% | 9.0% | 5.7% / 6.3% / **7.9%** |
| IF\|LOF\|AE | 92% | 95% / 96% / 97% | 15.0% | 11.7% / 9.8% / **14.2%** |
| RF | 62% | 39% / 39% / 38% | 5.4% | 3.0% / 2.9% / 1.9% |

- C(생성기만 학습 → 재생 정상 오탐): IF 17% · LOF 33% · AE 27%, AE 는 100명 중 83명을 한 번 이상 의심. 40명 때와 같은 수준.
- 지름길: 최대 `interval_cv` 0.811 — 없음.
- **늘린다고 계속 좋아지지 않는다**: 탐지는 IF 가 82% 까지 더 올랐지만, 오탐 감소폭은 40명 때보다 작다(AE 5.7~6.3% → 7.9%, 앙상블은 기준선 15.0% 근처 14.2%).
  해석(가설): 재생이 학습 정상의 다수(568 vs 생성기 ~150)가 되면 모델의 '정상'이 재생 쪽으로 옮겨 가고, **평가 정상은 생성기 출신**이라 오히려 덜 맞는다.
  즉 지금 평가셋으로는 '재생을 많이 넣을수록 좋다'를 잴 수 없다 — 실제 사람 정상으로 평가해야 결론이 난다.
- 주의: 40명(s0·s1)과 100명(s2)은 인원과 구성이 동시에 다르다. 인원 효과만 보려면 같은 시드에서 40·70·100 처럼 늘려야 한다.

### 3-6. 같은 사람 목록에서 인원만 바꾸기 — 40 ⊂ 70 ⊂ 100 (재생 시드 2)

100명 로그(§3-5)의 앞 40명·70명만 잘라 씀(사용자는 순서대로 재생되므로 서버 상태까지 동일 — 40·70명 피처가 100명 피처의 해당 행과 전부 일치 확인).
`awk -v k=40 '{split($1,a,"."); if (a[1]=="10"&&a[2]=="30"&&a[3]=="0"&&a[4]<=k) print}' data/otto_replay_s2_n100.log`
출력: `docs/35_결과/run_output_s2_n40.txt`, `_n70.txt`, (`_n100.txt` 는 §3-5)

| 모델 | A 탐지 | B 탐지 40 / 70 / 100 | A 오탐 | B 오탐 40 / 70 / 100 |
|---|---|---|---|---|
| IF | 43% | 71% / 81% / 82% | 5.2% | 4.9% / 5.4% / 5.4% |
| LOF | 91% | 88% / 88% / 88% | 10.1% | **7.1%** / 8.4% / 9.0% |
| AE | 87% | 97% / 95% / 95% | 9.0% | **5.7%** / 8.7% / 7.9% |
| IF\|LOF\|AE | 92% | 97% / 97% / 97% | 15.0% | **10.1%** / 14.4% / 14.2% |
| RF | 62% | 39% / 38% / 38% | 5.4% | 2.1% / 2.2% / 1.9% |

- **인원 효과가 분리됐다**: 같은 사람들에서 40 → 70 으로 늘리면 오탐 감소가 줄어든다(AE 5.7 → 8.7%, 앙상블 10.1 → 14.4%). 탐지는 IF 만 더 오르고(71 → 81%) 나머지는 그대로.
- 40명일 때 값은 다른 구성의 40명(s0 5.7%, s1 6.3%)과 같은 수준 → §3-5 의 '100명이 덜 좋다'는 구성 차이가 아니라 **인원(재생 비중) 때문**.
- C·지름길은 인원과 무관하게 비슷(C: IF 17% · LOF 33~42% · AE 26~28%, 지름길 최대 0.81).
- §3-5 가설과 맞는다: 재생 비중이 커질수록 모델의 '정상'이 재생 쪽으로 가고, 생성기 출신 평가 정상과 멀어진다.
  → 지금 평가셋 기준 최적은 '재생 ≈ 생성기 학습분과 비슷한 양'(40명 ≈ 230구간 vs 생성기 ~150구간)이지만, **이 최적값은 평가 정상이 생성기라서 생긴 것**일 수 있다. 실제 사람으로 평가하면 최적 비중이 달라질 수 있다.

## 4. 이 결과로 말할 수 있는 것 / 없는 것

- 말할 수 있음: 생성기 정상만으로는 사람 행동 모양의 정상을 14~26% 오탐한다(C). 재생 정상을 학습에 더하면 AE·IF 는 탐지를 유지하거나 올리면서 생성기 출발지 오탐도 내려간다(B, AE 9.0→5.7%).
- 말할 수 없음: **실제 사람에게도 오탐이 줄어든다.** 평가 정상(10.16.1.1xx)은 여전히 생성기 출신이고, 재생도 실제 사람이 아니라 'OTTO 시간 패턴 + 우리 매핑 규칙'이다. 검색·오류·리뷰는 재생에 없다.
- 재생 구성 2가지(시드 0·1, 각 40명)로 방향은 재현(§3-4). 100명(§3-5)은 탐지↑ 이지만 오탐 감소폭은 줄어듦 — 평가 정상이 생성기 출신인 한계가 드러남.
