# 02. Isolation Forest 개념 정리 (쉬운 버전)

> 2026-10-22 논의 정리. "ML은 어떻게 이상을 찾나, LLM과는 뭐가 다른가"

---

## 1. 한 줄 요약

**공격을 배우지 않는다. 평소(정상) 모습을 기준으로, "혼자 떨어뜨리기 쉬운 점"을 이상으로 본다.**

## 2. 운동장 비유

운동장에 학생 100명이 있다. 99명은 가운데 몰려 있고, 1명만 구석에 혼자 서 있다.
선생님이 **아무 데나 선을 그어** 운동장을 반으로 나누는 걸 반복한다.

- **구석의 학생** → 선 2~3번이면 혼자 남는다
- **무리 속 학생** → 선을 수십 번 그어야 겨우 혼자 남는다

👉 **"몇 번 만에 혼자 남았나?"** 가 판단 기준. 빨리 혼자 남을수록 수상하다.
이 과정을 트리 수백 개로 반복해 평균을 낸다(그래서 Forest).

| 운동장 | 보안 |
|---|---|
| 학생 | 접속 주체(IP) 또는 서버×5분 구간 |
| 위치 | 그 주체의 특징(지표) 값 |
| 무리 속 학생 | 평소 같은 정상 접속 |
| 구석의 학생 | 1분에 500번 로그인 실패하는 IP → **알럿** |

## 3. 자주 하는 오해

| 오해 | 실제 |
|---|---|
| 공격 사례를 학습한다 | ❌ 라벨 없이(비지도) 학습. 공격 예시 불필요 → 처음 보는 공격도 "평소와 다르면" 잡음 |
| 정상 점과의 **거리**를 잰다 | ❌ 거리를 안 잼. **잘라서 고립시키는 횟수(경로 길이)** 를 셈. 거리 기반은 kNN·LOF |
| 점의 **개수**를 센다 | ❌ 점 개수가 아니라 **선을 그은 횟수**를 셈 |
| 이상 = 공격 | ❌ 이상은 "평소와 다름"일 뿐. 월말 배치 작업도 걸림 → 사람 확인 필요 |

## 4. 지표(피처)는 더 넣어도 된다 — 단, 규칙이 있다

운동장 비유로 말하면 위치를 정하는 **축을 늘리는 것**(키 → 키+몸무게+달리기 속도).

| 종류 | 예시 |
|---|---|
| 접속량 | IP당 분당 요청 수, 계정당 요청 수 |
| 행동 패턴 | 조회한 서로 다른 고객 ID 수, 요청 간격의 규칙성(엔트로피) |
| 결과 | 에러(401/403/404) 비율, 응답 크기 |
| 환경 | 접속 시간대, 해외 IP 여부, 처음 보는 기기 |
| 시스템(모니터링) | CPU, 메모리, 네트워크 송/수신량, TCP 연결 수 |

규칙
1. **숫자로 바꾼다** — 해외 IP는 0/1, 국가는 빈도 등
2. **묶음 단위로 만든다** — 요청 한 줄이 아니라 "IP의 최근 5분", "서버의 5분"
3. **많을수록 좋은 게 아니다** — 선을 그을 축을 무작위로 고르므로 쓸모없는 지표가 많으면 둔해짐. 5~15개로 시작해 넣고 빼며 비교

## 5. ML vs LLM

| | ML (Isolation Forest) | LLM |
|---|---|---|
| 입력 | 숫자 | 글자(로그 원문, 요약) |
| 판단 근거 | **우리 데이터의 평소 모습** | **세상에서 배운 일반 지식** |
| 비유 | "얘 평소랑 다르네" | "이거 교과서에 나온 공격 수법이네" |
| 장점 | 빠르고 싸고 대량 처리, 신종 이상 | 왜 이상한지 문장으로 설명 |
| 약점 | 이유 설명 못 함 | 느리고 비쌈, 가끔 틀림, 우리 환경의 "평소"를 모름 |

→ 실전 구조: **ML이 수백만 건에서 후보 수십 건을 걸러내고, LLM이 그 후보만 읽고 설명**한다.
이 가설을 검증하는 실험이 `03_ML_vs_LLM_비교실험_계획.md`.
