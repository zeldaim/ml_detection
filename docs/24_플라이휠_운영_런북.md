# 24. 플라이휠 운영 런북 — 새 환경에 그대로 적용하는 절차

> 팀 인프라 등 **새 환경**이 서면 이 모델 과정을 처음부터 다시 돌려야 한다. 그때 바로 시작할 수 있게
> 전 과정을 **로직/알고리즘 + 자동화 스크립트 + 체크리스트**로 정리. 자동화: `scripts/flywheel_turn.sh`.
> 배경·근거: `docs/19`(원리), `docs/20`(설계), `docs/21`(실험 A~K), `docs/23`(개념도).

## 0. 알고리즘 (한눈에)

```
새 환경 온보딩:
  1. 로그 소스 확보       (nginx access log 또는 Wazuh archives.json)
  2. 출발지 분리 수단     (IP 별칭 or 실제 다중 호스트 → 정상/공격 구분)
  3. 기준선(정상) 수집    (공격 없는 깨끗한 구간, '현실적 속도'로)   ← 가장 중요
  4. 공격 변주 생성       (여러 종류 × fast/slow, 시작·끝 시각 기록)
  5. 하드 네거티브        (빠른 합법 클라이언트 = 상시 회귀 픽스처)
반복(플라이휠):
  6. 로그 수집 → features → (relative) → accumulate → supervised(검증)   = flywheel_turn.sh
  7. 지표 보고 피처/contamination 조정 → train_export(모델 버전 저장)
  8. 6~7 반복하며 데이터셋을 다양한 출처로 불림
```

## 1. 새 환경 온보딩 체크리스트

| 단계 | 할 일 | 우리 랩에서의 예 / 함정 |
|---|---|---|
| 로그 소스 | 앱 앞단 nginx `access_log`(combined) 확인. 경로·로테이션 파악 | `juiceshop_access.log` + `-YYYYMMDD` 로테이션 **둘 다** 합쳐야 함 |
| 출발지 분리 | 정상/공격을 **다른 출발지**로. 1대면 IP 별칭 | `ip addr add`; nginx 가 remote_addr=별칭 기록 |
| 정상 수집 | 공격 없는 구간, **사람 속도**(1~11 req/min). 여러 프로필·여러 IP·길게 | 너무 빠르면 공격과 인위적 겹침(§I). `collect_kit/target_side/normal_realistic.sh` |
| 공격 생성 | 여러 종류 × fast/slow, 시작·끝 UTC·출발지 기록(=라벨) | `real_attacks.sh`. 속도는 **현실적으로**(무sleep 금지, §J) |
| 하드 네거티브 | 빠른 합법 클라이언트(여러 경로) | `fastclient.sh`. 상시 회귀 검사 |
| 라벨 | 출발지 AND 시각 교집합만 공격. IP·UA 는 라벨 키일 뿐 **피처 금지** | IP형 정답지 `ip,label,type` |

## 2. 한 바퀴 돌리기 (자동화)

```bash
# 로그·정답지만 준비되면 한 명령:
scripts/flywheel_turn.sh --log data/<env>_access.log --answer data/<env>_answer.csv \
    --source <env>_$(date +%F) [--relative] [--contamination 0.1]
#  → features → (rel_*) → 누적셋 append → supervised 검증 → 현황 출력
```
DB 계층도 한 명령(팀 MySQL 서면 바로):
```bash
scripts/flywheel_turn.sh --log data/<env>_general.log --answer data/<env>_db_answer.csv \
    --source db_<env>_$(date +%F) --kind db    # db_features.py 경로, dataset_db.csv 로 자동
```

모델 버전 저장(운영 승격 후보):
```bash
python ml/train_export.py data/<env>_features.csv --answer data/<env>_answer.csv \
    --contamination 0.1 --out models/experiments/model_<env>_c010.joblib   # CHANGELOG 갱신
```

## 3. 판단 로직 (실험 A~K에서 굳힌 규칙)

- **합성은 개발·넓이용, 검증은 실제로.** 합성은 포화(전부 1.00)되기 쉬움 → 실제 held-out 필수.
- **정상이 병목.** 공격은 종류·변주(양 아님), 정상은 양+대표성. 정상 생성기 **속도 왜곡 주의**.
- **겹치면 축을 늘려라.** 속도 겹침 → `relative_features.py`(UEBA, §K). 내용 겹침 → `endpoint_entropy`(§J).
- **피처는 하나씩 추가 → 교차검증 통과해야 채택.** (seq_id_score 거부 vs entropy 채택)
- **모델 선택(실제 기준):** LOF 우수, IF 느린공격 취약, AE 분포 민감(대표 정상 필요). 조합 `IF|LOF|AE`도 평가.
- **모델 건강 의심되면 퍼뮤테이션 검사**(가짜 라벨 → 탐지 0 나와야 정상).
- **스키마 고정.** 피처 바꾸면 `accumulate.SCHEMA_VERSION` 올리고 과거분 재생성(섞지 말 것).

## 4. 환경 간 이식 시 주의 (편향)

- **행위 피처 위주**(요청률·간격·객체수·경로다양성)로. 환경 특이값(앱 전용 경로·UA) 의존 줄이기 → 전이성↑(`docs/19` §6-1).
- **출처 태그 필수**(`--source`): 환경/시기별로 섞이지 않게, leave-one-group-out 로 환경 편향 측정.
- **새 환경 첫 바퀴는 "소량 실제로 방향 확인" → 안정되면 대량**(sim-to-real).

웹과 데이터 민감도·출발지 귀속이 달라 분리. 착수 절차·LLM 데이터 위험·자산은 `docs/22`.
