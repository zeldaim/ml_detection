# 30. 운영 — 저장된 모델로 처음 보는 공격을 탐지할 때 필요한 것

> 작성일: 2026-10-26 · 상태: 정리 + 작은 수정(consumer·predict)
> 질문: 지금까지는 우리가 공격하고 정답지로 채점했다. **미리 모르는 공격을 로그로 분석할 때는** 학습 없이 완성된 모델만 있으면 되나? **joblib과 로그만 있으면 되나?**
> 관련: `inbox/README.md`·`ml/ingest.py`(입구), `docs/29`(로그 수신), `models/MODEL_CARD.md`(모델·경보 등급·한계), `docs/27` §4(v3 결함)

## 0. 답

- **학습은 필요 없다.** 정상 기간으로 한 번 학습해 저장한 번들(`train_export.py` → `.joblib`)을 불러 **점수만** 매긴다.
- 하지만 **joblib + 로그만으로는 안 된다.** 모델은 로그 원문을 못 읽는다. 학습 때와 **똑같이** 로그를 숫자 표로 바꾸는 과정이 앞에 있어야 한다.

| 필요한 것 | 왜 | 어디에 |
|---|---|---|
| 피처 추출 코드 | 모델 입력은 "출발지 × 5분" 숫자 표 | `ml/features.py`(웹) · `edge/db_features.py`(DB) · `edge/host_metrics.py`(호스트) |
| 같은 구간 길이 | 5분으로 학습하고 10분으로 세면 req_count가 2배 | 기본 5분, 바꿨다면 `meta.json`의 `window` |
| 같은 피처 순서·종류 | 순서가 바뀌거나 빠지면 **에러 없이 틀린 판정** | 번들 `features`·`feature_set`(`web_v1`) |
| rel_* 계산 | v3.1은 `rel_req_count`·`rel_max_req_1min`을 입력으로 받음 | `ml/relative_features.py --mode self` (§3 주의) |
| 스케일러·AE 경계·contamination | LOF·AE는 정상 기준으로 정규화된 값을 기대 | 번들 안에 같이 들어 있음 |
| 같은 scikit-learn 버전 | 다르면 로드 경고·결과 차이 | 번들 `sklearn` (현재 1.9.1) |

## 1. 실제로 돌리는 법 — 이미 있는 경로 3개

```
[다른 PC / 원격 Wazuh]                    [ML PC = 내 PC]
 Filebeat · Fluent Bit ──TLS──▶ Logstash ─▶ inbox/live/<출처>/<로그종류>/…log      (docs/29 §4)
 (또는 scp로 받은 파일)  ──────────────────▶ inbox/<이름>/                            (collect_kit/README §4)
                                                   │
                                                   ▼
                                  python ml/ingest.py <폴더>          ← 저장 모델로 판정만 (학습 없음)
                                  python ml/ingest.py <폴더> --retrain ← 그 인프라의 평소로 다시 학습
                                                   │
                                                   ▼
                                  <폴더>/out/REPORT.md · pred_*.csv
```

| 경로 | 명령 | 언제 |
|---|---|---|
| **입구(권장)** | `python ml/ingest.py inbox/live/lab/nginx` | 받은 로그 폴더를 그대로. 종류 판별 → 피처 → rel → `predict.py` → 보고서. 돌린 명령이 보고서에 남는다 |
| 손으로 | `features.py` → `relative_features.py` → `predict.py` | 단계별로 확인하고 싶을 때 (보고서 §2 명령을 복사) |
| 반복 | `consumer/consumer.py --nginx <로그> --model models/model.joblib --interval 60` | 한 호스트에서 주기적으로. **9피처(v2) 모델만** (§2) |

- 저장 모델 판정 = **우리 랩의 "평소"** 기준이다. 다른 인프라면 평소가 달라 오탐이 많을 수 있다 → `--retrain`과 비교 (`MODEL_CARD` §7)
- 정답지가 없으면 P/R/F1은 못 낸다. 이상 표시는 **조사 후보**이고, 경보 등급(합집합 = 티켓, LOF&AE = 고신뢰)은 `MODEL_CARD` §4

## 2. 이번에 고친 것 (2026-10-26)

### 2-1. `consumer.py` — AE 누락, 없는 피처를 0으로 채움
- **AE를 빼고 IF·LOF만** 보고 있었다 → `predict.py`와 같은 **IF|LOF|AE**로. 확인: 정본 로그 + `model.joblib`에서 consumer 경보 118 = predict 이상 118 (같은 구간)
- 번들 피처를 `feat.get(c, 0)`으로 읽어서, **v3.1을 넣으면 rel_* 두 열이 조용히 0**인 채 판정했다 → 이제 이유를 출력하고 멈춘다 (rel 모델은 `ingest.py`로)

### 2-2. `predict.py --block-file` — 차단 연계용 기록 (아직 미연결)
- 이상 구간의 출발지를 `ML_ANOMALY srcip=<IP> window=… models=LOF+AE rf=…` 한 줄씩 덧붙인다 (`detector/wazuh_ml_detect.py`와 같은 형식)
- **우리는 아직 Active Response를 쓰지 않는다.** 이 파일은 경보 기록일 뿐이다. 나중에 Wazuh localfile → 커스텀 룰 → Active Response(`docs/01`) 또는 SOAR(`docs/04`)가 이 파일을 읽으면 차단으로 이어진다
- 오탐이면 정상 IP를 끊게 되므로 자동 차단을 연결할 때는 고신뢰 등급(LOF&AE)만 쓰는 것을 전제로 한다 (`MODEL_CARD` §4)

## 3. 처음 보는 공격일 때 알아둘 것

- **처음 보는 공격을 잡는 건 비지도(IF·LOF·AE)다.** RF는 학습한 10종 중 가장 닮은 이름을 붙일 뿐이다. 새 종류면 이름이 엉뚱하게 나오니 경보 근거는 IF/LOF/AE로 본다 (`docs/12`)
- **rel_*는 들어온 로그 안에서 계산된다.** `--mode self`는 각 출발지의 앞 40% 구간을 "평소"로 본다. 그래서 **공격만 하는 새 IP는 자기 공격이 기준이 되어 배수가 1 근처(정상처럼)**로 나온다 (`MODEL_CARD` §7 한계 표에 등록된 문제)
  - 실측: 학습에 쓰지 않은 `boost_bola_slow`(새 IP 6개, 36구간)를 `ingest.py` 판정 모드로 돌리면 **36/36 탐지**. 이 공격은 rel이 아니라 `uniq_objects`·`interval_cv` 같은 다른 피처로 잡힌다
  - 속도만 다른 공격(평소 느리다가 갑자기 빨라지는 탈취형)은 rel이 핵심이므로, 새 IP에 대해서는 `peer`/`expanding` 기준선이나 학습 기간 기준선 저장이 필요하다 → `docs/27` §7 다음 할 일
- **합집합 경보는 오탐이 쌓인다.** contamination 0.05는 모델 하나당 정상의 약 5%다. 셋의 합집합이면 최대 약 15%까지 늘어난다
- **정상은 변한다.** 사용자 증가, 새 API, 이벤트 기간이면 오탐이 는다 → 최근 정상으로 `--retrain`, 버전 규칙은 `models/README.md`
- **확인한 경보는 정답지로 쌓는다.** 그게 다음 평가와 재학습의 재료가 된다 (플라이휠, `docs/24`)
