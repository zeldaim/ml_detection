# 16. 레퍼런스 — 논문·데이터셋·프로젝트·연구 공동체

> 작성일: 2026-10-24 · 목적: 우리 주제(룰이 놓친 API/웹/DB 이상행위를 ML로 탐지)를 실제 연구·실무가 어떻게 다루고 결론 내는지 참고. 일부(최신 arXiv)는 웹 검색 결과이며 세부는 직접 확인 필요.

## 0. 우리 결론을 뒷받침하는 발견 (중요)

검색에서 **우리 실험 결론과 같은 이야기**가 독립적으로 확인됐다:

- **"Isolation Forest는 학습 때 본 값의 범위 안에서만 분할하므로, 본 적 없는 값으로 외삽(extrapolate)을 못 한다."** → 우리가 느린 BOLA에서 IF가 놓치고 LOF가 잡은 현상과 정확히 같은 원리(`docs/13` §4 H5).
- Autoencoder·다른 방법은 "모든 피처를 재구성"하거나 국소 밀도를 봐서 IF의 약점을 보완한다는 비교 연구들이 있다. → 우리 다음 모델 후보로 **Autoencoder**가 타당함을 시사.

즉 우리 프로젝트의 "IF만으론 부족, 보완 모델이 필요"는 학계·실무에서도 통용되는 결론이다.

## 1. 핵심 알고리즘 원논문 (우리가 쓰는 모델의 출처)

| 모델 | 논문 | 비고 |
|---|---|---|
| Isolation Forest | Liu, Ting, Zhou, "Isolation Forest", ICDM 2008 | 우리 IF |
| Local Outlier Factor (LOF) | Breunig et al., "LOF: Identifying Density-Based Local Outliers", SIGMOD 2000 | 우리 LOF (국소 이상치) |
| One-Class SVM | Schölkopf et al., 2001 | 우리 OCSVM |
| Random Forest | Breiman, "Random Forests", 2001 | 우리 RF |

이 4개는 scikit-learn 문서의 각 추정기 페이지에도 참고문헌으로 걸려 있다. 완벽 가이드 해당 챕터와 함께 보면 됨.

## 2. 데이터셋 (정상/공격 라벨이 있는 공개 벤치마크)

우리처럼 "정상 vs 공격"을 채점하려면 공개 데이터셋으로 교차검증하면 좋다.

| 데이터셋 | 내용 | 우리와의 관련 |
|---|---|---|
| **CSIC 2010 HTTP** | 스페인 CSIC의 웹 요청(정상/공격, SQLi·XSS·파라미터 변조) | **웹 계층에 가장 적합** (`docs/07`에서 이미 후보로 언급) |
| CICIDS2017 / CSE-CIC-IDS2018 | 네트워크 플로우 기반 침입(브루트포스·DoS·웹공격 등) | 플로우 피처 비교군 |
| UNSW-NB15 | 네트워크 트래픽, 현대적 공격 | IDS 벤치마크 |
| NSL-KDD | KDD'99 개선판 (고전) | 입문·비교 기준선 |
| CERT Insider Threat (CMU SEI R4.2) | 사용자 활동 로그 | **UEBA**(사용자 행위) 스타일 참고 |

> 주의: CICIDS·UNSW는 **네트워크 플로우**라 우리 "앱/DB 행위"와 결이 다름. 웹 계층엔 **CSIC 2010**이 제일 가깝다. API 전용 공개 벤치마크는 아직 드물다(검색상 확립된 표준 없음).

## 3. 우리 주제와 직결되는 최신 논문 (검색, 세부 미검증)

- **Few-Shot API Attack Anomaly Detection** (arXiv 2405.11247) — 정상 웹 트래픽으로 학습해 비정상 API 요청을 탐지(정상 36k 학습 / 비정상 25k 추론). 우리 접근(정상 기준 학습)과 같은 뼈대. 방법 논문.
- **A Novel Anomaly Detection Approach to Secure APIs** (CEUR-WS Vol-3125, 2021) — "모든 API는 고유 접근 패턴이 있어 정적 정책으론 부족" → K-Means·RF·Autoencoder로 학습. 우리 "피처로 행위 학습"과 동일 논지.
- **BLADE: Behavior-Level Anomaly Detection Using Network Traffic in Web Services** (arXiv 2511.05193) — 웹 서비스 행위 수준 이상탐지.
- **X-WAD: eXplainable Web Anomaly Detection** (arXiv 2608.27172) — **설명가능성**(왜 이상이라 했나). 우리 RF 피처 중요도·LLM 설명과 연결.
- **Context-Aware Web Attack Detection in Open-Source SIEM via MITRE ATT&CK Behavioral Profiling** (arXiv 2605.13337) — **오픈소스 SIEM(Wazuh류) + 행위 프로파일 + MITRE 매핑**. 우리 구성과 거의 동일 주제.
- **Zero-Day Web Attacks with LSTM/GRU/Stacked Autoencoder Ensemble** (arXiv 2504.14122) — 딥러닝 앙상블로 제로데이 웹 공격. "룰이 못 잡는 새 공격" 문제의식 동일.
- **Comparing Autoencoder and Isolation Forest in Network Anomaly Detection** (Smolen & Benova, ResearchGate) — **IF vs Autoencoder 비교**: AE가 제로데이에 유리, IF는 estimator 튜닝 필요. 우리 IF 한계 논의의 근거.

## 6. 이 레퍼런스를 우리 프로젝트에 어떻게 쓰나

1. **방법 검증:** Few-Shot API / CEUR 논문처럼 "정상 학습 → 이상 탐지"가 표준 접근임을 확인 → 우리 방향이 맞다.
2. **데이터 교차검증:** CSIC 2010으로 같은 파이프라인을 돌려 "우리 랩 데이터 결과가 공개 데이터에서도 재현되나" 확인(`docs/07`).
   - **주의(실측):** CSIC은 **요청 내용(페이로드) 공격**(SQLi·XSS)이라 우리 **행위 피처**로는 잘 안 잡힌다(초기 실행 Recall 0.15~0.24). `ml/load_csic.py`를 **내용 피처**(sqli/xss/특수문자/경로길이)로 바꾸고 정상만 학습(--train-until)하면 공정해진다. 교훈: **내용 기반 탐지 ≠ 행위 기반 탐지** — 우리 프로젝트는 행위 기반이므로 CSIC은 '파이프라인이 외부 데이터에서도 도나' 확인용이고, 행위 공정비교엔 행위형 데이터가 필요.
3. **다음 모델:** IF vs AE 비교 논문 → **Autoencoder를 비지도 층에 추가**해 IF·LOF와 비교(우리 `supervised.py` 틀에 모델 하나 더).
4. **설명가능성:** X-WAD → 우리 RF 피처 중요도·LLM 설명을 "왜 이상인가" 관점으로 정리.
5. **보고서 인용:** 발표/제안서에 OWASP API Top10 + 위 논문으로 "학계·실무도 같은 결론"이라는 근거.

> 인용할 때는 arXiv 항목의 저자·연도·게재처를 **원문에서 직접 확인**하고 쓸 것(이 문서의 arXiv 항목은 검색 스니펫 기준, 미검증).
