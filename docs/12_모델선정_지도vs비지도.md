# 12. 모델 선정 — 지도(Random Forest) vs 비지도(Isolation Forest), 함께 쓰는 근거

> 작성일: 2026-10-23 · 상태: 논의 정리 + 실험 설계 + 예비 결과(샘플)
> 배경: 팀 논의에서 "지금 모델은 정상만 학습하니, 비정상(공격)을 학습하는 Random Forest를 쓰자, 통계 분석에 유리하니 RF에 집중하자"는 제안이 나왔다.
> 관련: `09` Q4·Q8(비지도 결정), `10` §3(모델), `11` §2(룰 밖 탐지 방법), `ml/supervised.py`(비교 실험 코드)

---

## 0. 결론

- 두 모델은 경쟁이 아니라 **잡는 공격이 다르다** → **함께 쓰는 구조**를 제안하고, 그 타당성을 §5 실험으로 입증한다
- 하나만 고르면 **Isolation Forest(비지도)** — 프로젝트 목표가 "룰이 놓친, 처음 보는 공격"이고 공격 데이터가 적기 때문
- RF는 **알려진 공격의 정밀 분류 + 피처 중요도(설명)** 역할로 둔다

## 1. 차이

| | 현재 (비지도 + 통계) | 제안 (Random Forest = 지도학습) |
|---|---|---|
| 모델 | Isolation Forest, LOF, OCSVM, Z-score | Random Forest (결정 트리 여러 개의 다수결) |
| 학습 데이터 | **정상만** (라벨 불필요) | **정상 + 공격, 둘 다 라벨 필요** |
| 묻는 것 | 평소와 다른가? | 학습한 공격과 닮았나? |
| 강점 | **처음 보는 공격**, 느린 공격, 변형 | **학습한 종류**를 정확히, 오탐 적음 |
| 약점 | 정상만 있어도 일정 비율 경보(오탐), 공격 종류를 모름 | **학습에 없던 공격을 놓침** |
| 필요한 공격 데이터 | 채점용 소량 | 종류별로 충분히 |
| 설명 | 약함 → LLM 설명으로 보완 (`ml/explain_llm.py`) | **피처 중요도**로 "무엇이 판단에 쓰였나" 제시 |

### 용어 정리
- **Isolation Forest는 비정상을 학습하지 않는다.** 이름에 "Forest"가 있지만 정상만 보고 "빨리 고립되는 점"을 찾는 비지도 모델이다. 제안의 "포레스트"가 이것이라면 이미 쓰고 있다
- **"RF가 통계 분석에 유리하다"는 정확하지 않다.** RF는 분류기다. 장점은 **피처 중요도를 통한 설명력**이다. 통계적 기준선은 Z-score(`10` §3-1)가 맡는다

## 2. 함께 쓰는 구조

```
로그 → 피처 ─┬─ 룰                       : 알려진 패턴, 빠름
             ├─ Random Forest (지도)      : 학습한 공격 종류를 정밀 분류
             └─ Isolation Forest (비지도) : 처음 보는 이상 탐지
                         ↓
         여러 방법이 함께 지목한 구간 우선 → LLM 설명 → 판단 (룰·점수가 결정)
```

- 같은 피처 표·같은 정답지·같은 채점표를 쓰므로 추가 비용은 **라벨 있는 공격 데이터**뿐

## 3. 하나만 고른다면 — Isolation Forest

| 기준 | Isolation Forest | Random Forest |
|---|---|---|
| 프로젝트 메시지 "룰이 놓친 공격" | **부합** — 아무도 정의 안 한 이상을 찾음 | 약함 — 아는 공격을 다시 학습 |
| 데이터 상황 (공격 소량, 기간 짧음) | **부합** | 공격 데이터 부족 |
| 새 형태(느린 공격, 자동화 도구 변형) | **강함** | 학습에 없으면 놓침 |
| 설명력 | LLM 설명으로 보완 | 피처 중요도 |

## 4. 함께 쓸 때의 함정

| 함정 | 설명 | 대응 |
|---|---|---|
| **사건 누수** | 같은 공격 사건을 5분 구간으로 잘라 학습·평가에 나눠 넣으면 RF가 "그 사건"을 외워 점수가 부풀려짐 | **공격 사건(또는 종류) 단위로 통째로** 빼서 평가 (leave-one-group-out) |
| **출처 학습** | 공격만 특정 IP 대역·시간대에서 오면 RF는 공격이 아니라 출처를 학습 (`05` §1) | IP·시간 피처 미사용, 공격·정상 출처 섞기 |
| **채점 데이터로 튜닝** | 평가 결과를 보며 임계값을 바꾸면 과대평가 | 임계값은 학습 데이터로만 결정 |
| 라벨 품질 | 정답지 시간이 틀리면 정상 구간이 공격으로 라벨됨 | 정답지 UTC 기록, 시작·끝 여유 확인 |

## 5. 타당성 입증 실험

### 5-1. 가설

| # | 가설 | 확인 방법 |
|---|---|---|
| H1 | RF는 **학습한 종류의 다른 사건**을 높은 정밀도로 잡는다 | E1 |
| H2 | RF는 **학습에 없던 종류**를 놓친다 | E2 |
| H3 | IF는 학습에 없던 종류도 잡지만, 정상 구간 오탐이 있다 | E2, E3 |
| H4 | **RF+IF(OR)** 는 각각보다 탐지율이 높고, 오탐은 IF 수준에 머문다 | E1, E2 |

### 5-2. 실험

| 실험 | 방법 | 명령 |
|---|---|---|
| E1 아는 공격 | 공격 **사건** 하나씩 빼고 학습 → 뺀 사건 평가 (같은 종류의 다른 사건은 학습에 있음) | `ml/supervised.py … --group-by attack` |
| E2 처음 보는 공격 | 공격 **종류** 하나씩 빼고 학습 → 뺀 종류 평가 | `ml/supervised.py … --group-by type` |
| E3 정상 오탐률 | 정상 기간만으로 각 모델의 경보 비율 | `ml/models.py --train-until …` 후 정상 구간 집계 (`ml/README.md` ⚠️ 절) |

지표: 공격 구간 탐지율, 정상 구간 오탐률, RF 피처 중요도. 정상 평가 구간은 시간순 뒤쪽 30%(`--normal-train 0.7`).

### 5-3. 팀에 필요한 데이터

- 정상 수집 기간 (`08` §3) — 공격 없이 충분히
- 공격 **종류 2개 이상**, 종류마다 **사건 2~3개 이상** (E1은 같은 종류의 사건이 2개 이상이어야 가능)
- 정답지: 시간 구간형 `attack_id,src,start,end,type` (UTC). `type`이 E2의 묶음 기준
- 공격 생성은 통제된 랩에서 팀이 직접 수행 (`09` 안전 제약 메모)
