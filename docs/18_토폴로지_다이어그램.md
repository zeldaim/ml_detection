# 18. 토폴로지·다이어그램 (draw.io 밑그림 "정답")

> draw.io로 다시 그릴 때 쓰는 기준. 각 그림은 **ASCII 배치 + 노드 목록 + 연결(화살표) 목록**으로 준다.
> IP·네트워크는 현재 랩 기준(VMware NAT = VMnet8, 10.16.1.0/24, 게이트웨이/DNS 10.16.1.2, 호스트 10.16.1.1).

---

## 그림 1. 현재 랩 네트워크 토폴로지 (실제 구성)

```
                         호스트 PC (Windows, VMware Workstation)
                         10.16.1.1  ·  ML 분석(scikit-learn)
                                │  VMnet8 (NAT, 10.16.1.0/24)
        ┌───────────────────────┼───────────────────────┐
        │                       │                       │
 ┌──────────────┐      ┌─────────────────┐      ┌──────────────┐
 │ Kali (공격)   │      │ 취약 서버 Rocky  │      │ (예정) Wazuh  │
 │ 10.16.1.x    │─────▶│ 10.16.1.10      │      │  매니저       │
 │ 보조 .211~214│ 공격 │ Juice Shop+nginx│      │  (SIEM)      │
 └──────────────┘      │ (+ MySQL 예정)  │      └──────────────┘
                       │ 정상 보조 .101~106       ▲
                       └─────────────────┘       │ (로그 전송, 예정)
                                │ 로그 scp        │
                                └────────────────┘→ 호스트 PC(ML)
```

**노드**
- 호스트 PC (Windows) — 10.16.1.1 — 역할: VMware 호스트 + ML 분석
- VMnet8 — NAT 네트워크 10.16.1.0/24 (게이트웨이·DNS 10.16.1.2)
- 취약 서버 (Rocky Linux) — 10.16.1.10 — Juice Shop(127.0.0.1:3000) + nginx(80) [+ MySQL 예정]
  - 정상 트래픽 보조 IP: 10.16.1.101~106
- Kali (공격자) — 10.16.1.x — 공격 보조 IP: 10.16.1.211~214
- (예정) Wazuh 매니저 — SIEM 중앙 수집

**연결(화살표)**
- Kali 10.16.1.211~214 ──공격(HTTP)──▶ 취약서버 10.16.1.10:80
- 정상 생성기(보조 IP .101~106) ──정상 트래픽──▶ 10.16.1.10:80
- 취약서버 nginx 로그 ──scp──▶ 호스트 PC(ML 분석)
- (예정) 취약서버 Wazuh 에이전트 ──로그──▶ Wazuh 매니저

## 그림 2. 목표 데이터센터 토폴로지 (확장형, docs/13 §8)

```
   [인터넷/공격자]
         │
   ┌───────────┐   경계 방화벽: L3/L4·시그니처는 막지만
   │  pfSense  │   문법 정상 공격(BOLA·느린공격)은 통과
   └───────────┘
         │ (DMZ)
   ┌───────────┐        ┌───────────┐
   │ 웹 티어    │───────▶│ DB 티어    │
   │ nginx+PHP │ 쿼리    │ MySQL     │
   │ +에이전트  │        │ +에이전트  │
   └───────────┘        └───────────┘
         │ 로그                │ 로그
         └──────────┬──────────┘
                    ▼
            ┌───────────────┐        ┌──────────────┐
            │ Wazuh 매니저   │───────▶│ ML 분석/소비자 │
            │ (SIEM, 중앙)   │ archives│ IF·LOF·AE·RF │
            └───────────────┘  또는   └──────────────┘
                    ▲          엣지 벡터
            syslog  │
         [pfSense·스위치 등 에이전트 불가 장비]
```

**노드**
- pfSense — 경계 방화벽/라우터 (DMZ 분리)
- 웹 티어 — nginx + PHP 취약앱 + Wazuh 에이전트
- DB 티어 — MySQL + Wazuh 에이전트 (웹과 분리된 세그먼트)
- Wazuh 매니저 — 중앙 SIEM (여러 에이전트 로그 집약)
- ML 분석/소비자 — IF·LOF·AE(발견) + RF(분류)
- 에이전트 불가 장비(pfSense 등) — syslog로 전송

**연결**
- 인터넷/공격자 ──▶ pfSense ──▶ 웹 티어 (경계 통과)
- 웹 티어 ──쿼리──▶ DB 티어
- 웹·DB 에이전트 ──로그──▶ Wazuh 매니저
- pfSense 등 ──syslog──▶ Wazuh 매니저
- Wazuh 매니저 ──archives(전체 로그)──▶ ML 분석
- (엣지 방식이면) 각 티어 ──피처 벡터만──▶ 중앙 collector

**강조 포인트(색/주석용):** pfSense에서 "통과 ✅"를, ML에서 "여기서 탐지 🚨"를 대비시키면 defense-in-depth 메시지가 산다.

## 그림 3. 탐지 파이프라인 (데이터 흐름)

```
 로그 ─▶ features ─▶ 모델 ─────────────────▶ 판정
 (nginx/   (출발지     ┌─ 비지도(발견) ─┐  ┌지도(분류)┐
  MySQL)    ×5분)      │ IF · LOF · AE │+ │   RF    │ ─▶ 🚨 이상 + 공격종류
                      └───────────────┘  └─────────┘       │
                            정상으로 학습        라벨로 학습   └▶ 채점 P/R/F1
                                                             (evaluate.py)
```

**노드(단계):** 로그 → features.py → [비지도 IF·LOF·AE] + [지도 RF] → 판정 → evaluate(P/R/F1)
**연결:** 각 단계 직렬. 비지도는 "정상 구간으로 학습", 지도(RF)는 "라벨(정답지)로 학습" — 두 입력을 다르게 표시.

## 그림 4. 2계층 탐지 구조 (핵심 결론)

```
         들어온 로그(구간)
               │
   ┌───── 1층: 발견 (비지도) ─────┐
   │  IsolationForest  전역 이상   │
   │  LOF              국소 이상   │  ← 느린 BOLA는 IF 놓침 / LOF·AE 잡음
   │  Autoencoder      재구성 오차 │
   └──────────────┬───────────────┘
                  │ 이상으로 지목된 구간
   ┌───── 2층: 분류 (지도) ───────┐
   │  RandomForest  → 공격 종류    │  (brute_fast / bola / sqli / 정상)
   └──────────────┬───────────────┘
                  ▼
         🚨 "무엇이, 무슨 공격"
```

**메시지:** 1층(발견)만으론 "이상하다"까지, 2층(분류)만으론 "본 적 없는 건 놓침". **둘을 합쳐야** 발견+식별.

## 그림 5. 자동화 배포 — 단순(consumer) vs 엣지(edge)

```
[단순]  원본 로그 ──전체──▶ consumer (분석 PC) ──▶ 저장모델 판정 ──▶ 🚨

[엣지]  웹 호스트 ─피처 벡터만─┐
        DB 호스트 ─피처 벡터만─┼─▶ collector(중앙) ─▶ 저장모델 판정 ─▶ 🚨
                              │     + 스풀 적재
         (원본 로그는 호스트 밖으로 안 나감)
```

**차이(주석):** 단순=중앙이 원본 로그를 읽음 / 엣지=각 호스트가 벡터만 보냄(대역폭·개인정보 유리, 다중 호스트 확장).

## 그림 6. DB 출발지 귀속 (edge/correlate.py)

```
문제: DB는 '앱 서버 하나'만 본다 → 공격자별 구분 불가

[옵션 C 티어]  DB 로그 전체 ─▶ 구간별 1행(티어) ─▶ "DB 티어가 공격받나"
[옵션 A 상관]  웹 피처(IP×구간) + 같은 구간 DB 집계(db_*) ─▶ 웹 IP에 귀속
```

**노드/연결:** 옵션 C = DB로그→티어 집계→모델. 옵션 A = (웹 피처)+(DB 티어 집계) 시간 구간으로 join→모델.

## 그림 7. 공격 단계 ↔ 탐지 (OWASP/MITRE 매핑, docs/15)

```
침투(T1190)        실행            지속성(T1547)        정찰·유출
섀도우API 악용  ─▶ 명령 실행   ─▶  Run키/계정   ─▶  내부탐색·대량유출
  │                 │                │                 │
웹·API 로그      Sysmon EID1      Sysmon13/FIM     호스트·네트워크
  │                 │                │                 │
ML(이상요청)      Wazuh 룰        Wazuh 룰          ML 상관분석
```

**메시지:** API 취약점은 "문"(침투 경로), 탐지 대상은 "들어온 뒤의 행위"다.

## draw.io 그릴 때 팁

- **박스 종류를 색으로 구분:** 공격자(빨강), 네트워크/방화벽(회색), 서버(파랑), ML/분석(초록), 로그/데이터(노랑).
- **화살표 라벨**을 꼭 달기: "공격", "로그", "피처 벡터", "scp", "syslog" 등 — 흐름의 의미가 그림의 핵심.
- 그림 1(현재)과 그림 2(목표)를 **나란히** 두면 "지금 → 확장" 스토리가 된다.
- 그림 4(2계층)는 발표 표지/핵심 슬라이드용으로 가장 임팩트 큼.
