## 2. 검증 실험과 결과 (사실 근거)

### 실험 A — Juice Shop 2종 합성(기존), 처음 보는 공격(leave-one-type-out)
입력: `features_combined.csv`(44구간) · 정답지 `answer.csv`(brute_fast, bola) · `supervised.py --group-by type`

| 모델 | 처음 보는 공격 탐지율 | 정상 오탐률 |
|---|---|---|
| RF(지도) | 0.29 | 0.00 |
| IF | 0.43 | 0.00 |
| LOF | **1.00** | 0.00 |
| AE | **1.00** | 0.00 |
| IF\|LOF\|AE | 1.00 | 0.00 |

> **IF가 놓치고 LOF가 잡은 느린 BOLA 구간 4개(H5)** 재확인. RF는 학습에 없던 종류를 못 잡음(0.29).
> = 프로젝트 핵심 결론(`docs/13`) 재현.

### 실험 B — 다양 합성 10종(신규), 처음 보는 공격
입력: `gen_synth_log.py`(240분·정상 8명·공격 10종×2, 로그 18,438줄 → 418구간, IP 28개) · `supervised.py`

| 모델 | 탐지율 | **정상 오탐률** |
|---|---|---|
| RF(지도) | 0.91 | 0.00 |
| IF | 1.00 | 0.15 |
| LOF | 1.00 | 0.09 |
| AE | 1.00 | **0.06** |
| IF\|LOF\|AE | 1.00 | 0.18 |

RF 피처 중요도(상위): `endpoint_entropy`(0.32) · `uniq_paths`(0.30) · `interval_cv`(0.15) · `err_ratio`(0.11).

> **해석(중요):** 정상을 **현실적으로 다양하게** 만들자, 전엔 0이던 **비지도 오탐이 6~18%로 드러났다**(contamination 0.1 효과, `docs/17`). 데이터가 현실에 가까워졌다는 신호.
> 이번엔 H5=0(합성 느린 공격이 IF에도 걸림) → **합성이 실제 느린 공격의 미묘함을 다 담지 못함** = 실제 검증이 필요한 이유.

### 실험 C — CSIC 공개데이터 (방법 보정 필요)
`features_csic.csv`로 빠르게 돌렸으나 `--train-until`(정상 기간 분리) 없이 fit 해 **기준선이 오염** → 수치 무효.
내용 피처 기반의 올바른 결과는 `docs/13`(lof/AE 고F1) 참조. CSIC은 **내용 공격**이라 행위 피처와 축이 다름(`docs/16`).

### 실험 D — contamination 스윕 (2026-10-25, 실험 1 수행)
입력: 실험 B와 같은 합성 10종. `supervised.py --contamination {0.1,0.05,0.03,0.01}`. **모든 설정 탐지율 1.00 고정.**

| contamination | IF 오탐 | LOF 오탐 | AE 오탐 |
|---|---|---|---|
| 0.10 | 0.15 | 0.09 | 0.06 |
| 0.05 | 0.06 | 0.03 | 0.05 |
| 0.03 | 0.03 | 0.03 | 0.03 |
| **0.01** | 0.03 | **0.01** | **0.01** |

> **탐지율은 1.00 유지, 오탐만 급감** → 합성 기준 권장 **0.01**. 단 탐지율이 전부 1.00인 것 자체가
> **합성이라 공격이 과하게 분리**됨을 뜻함 — 실제 로그에선 재조정 필요. 버전 모델 4종 저장: `models/experiments/`.

### 실험 E — 피처 v2 후보 `seq_id_score` (실험 2 수행 → **데이터가 거부**)
가설(LLM식 제안): 소유자원 객체 ID가 **연속**이면 BOLA 열거(1,2,3,…). coverage = 접근 ID수/(max-min+1).

1차(임계 ID 3개): 정상 쇼핑객도 자기 장바구니 1,2,3 접근 → seq=1.0 **오염** → 오탐↑(IF 0.06→0.09).
2차(임계 10개, 진짜 열거만): 공격 5구간에서만 발화(오염 제거). 그러나 교차검증(c=0.05):

| | IF 오탐 | LOF 오탐 | AE 오탐 |
|---|---|---|---|
| seq_id_score 있음 | 0.10 | 0.03 | 0.04 |
| 없음(drop) | 0.06 | 0.03 | 0.05 |

> **판정: 채택 보류.** 이 합성 데이터에선 `uniq_objects`가 이미 BOLA를 잡아 **중복**, 탐지율이 이미 1.00이라
> 새 차원은 노이즈만 더함(IF 악화). → 코드 되돌림(v1 스키마 유지), 실제/더 어려운 데이터에서 재검증 대상.
> **= "피처 제안은 LLM, 선택은 데이터"(docs/19 §2-1·§7)의 실제 사례.** 그럴듯한 가설도 데이터가 거부하면 뺀다.

### 실험 F — **실제 로그 검증** (2026-10-25, 첫 실제 바퀴) ★
`10.16.1.10` Juice Shop nginx `juiceshop_access.log`(combined) → `features.py`(실 48구간, IP 13개).
공격 IP 전용(.211/.212 brute_fast, .213/.214 bola)으로 IP형 정답지. `supervised.py --group-by type`.

| 모델 | 실제 탐지율 | 정상 오탐률 |
|---|---|---|
| IF | **0.43** (느린 공격 놓침) | 0.15 |
| LOF | **1.00** | 0.08 |
| AE | **1.00** | 0.15 |
| IF\|LOF\|AE | 1.00 | 0.15 |

> **IF가 놓치고 LOF/AE가 잡은 구간 4개 (H5) — 실제 로그에서 재현.** RF 중요도: err_ratio(0.31)·uniq_objects(0.15).
> **중요:** 합성에선 IF도 1.00(포화)이었는데 **실제에선 IF 0.43** → ⑴합성이 쉬웠던 게 맞고 ⑵**모델은 정상**(실험 D·퍼뮤테이션과 일치), ⑶실제가 **포화 안 된 진짜 기울기**를 준다.
> 한계: 공격 구간 7개로 적음(지표 흔들림), 2일치 로그 혼재. 더 많은 실제 변주 필요.
> 축적: 플라이휠 누적셋에 48행(`source=real_juiceshop_2026-10-24`), 모델 `models/experiments/model_real_juiceshop_c005.joblib`.

### 실험 G — **실제 다중 IP·9종 공격** (2026-10-25, 두 번째 실제 바퀴) ★
타겟에 공격 IP 별칭(.221~.227)을 붙여 7종을 **동시에** 생성 + 정상(.101~106) 동시. nginx 가 별칭을 remote_addr 로 기록.
첫 수집(.211~214)과 합쳐 9종·70구간. `supervised.py --group-by type`.

| 모델 | 탐지율 | 정상 오탐 | 메모 |
|---|---|---|---|
| **LOF** | 1.00 | **0.06** | 실제 데이터 최고 |
| IF | 0.71(c0.1)→0.41(c0.05) | 0.06 | 느린 공격 놓침 |
| **AE** | 1.00 | **0.88** | contamination 무관하게 높음 → 분포 shift 문제 |
| RF\|IF\|LOF | 1.00 | 0.12 | |

> **IF가 놓치고 LOF가 잡은 구간 5개 (H5) — 실제 다종 데이터에서 강하게 재현.**
> **AE 오탐 0.88 = 편향/분포 shift의 실제 사례**: 두 번에 나눠 수집한 정상(시간대·상황 다름)이 서로 다른 분포라,
> 한쪽으로 학습한 AE가 다른 쪽 정상을 이상으로 봄(train≠eval normal). contamination 으로 안 고쳐짐
> → **AE는 대표성 있는 정상이 더 필요**(양보다 다양성·분포 일치). LOF는 국소 밀도라 견딤.
> **합성(전부 1.00)과 달리 실제는 LOF>IF, AE 취약으로 갈림 = 실제가 주는 진짜 기울기.**
> 축적: 누적셋 532행(실제 70 포함), 모델 `models/experiments/model_real_v2_c010.joblib`.

### 교훈 (실제 2바퀴 종합)
- **실제 데이터는 모델을 구분시킨다**: 합성 포화(모두 1.00) → 실제선 LOF 우수, IF 느린공격 취약, AE 분포민감.
- **AE 분포 shift**는 "같은 환경 데이터만으론 편향"의 직접 증거 → 다양·대표 정상이 답(편향-분산).
- 운영 후보는 현재 **LOF**(실제 1.00/0.06). AE 는 정상 보강 후 재평가.

## 3. 핵심 통찰 (이번 대화에서 굳힘)

1. **`fit()`은 덮어쓴다, 쌓이지 않는다.** 똑똑해지려면 데이터셋을 쌓아 **재학습**. 모델 파일을 반복 저장한다고 성장하지 않음.
2. **피처 vs 라벨은 다른 행위.** 피처=내가 던지는 질문(제안은 사람/LLM, **선택은 데이터**). 라벨=정답지(**사실 기록**, LLM 대행 불가 — 추측이 됨).
3. **양보다 다양성.** 같은 공격 반복은 포화·과적합. 여러 변주·여러 종류라야 일반화. 깊이≠넓이. 처음 보는 종류는 비지도 몫.
4. **공격 로그는 양이 중요치 않다. 정상이 병목.** 비지도는 공격을 학습에 안 씀(공격=측정용). 지도도 변주가 핵심. **양이 필요한 건 현실적 정상.** 단 공격은 종류당 지표가 흔들리지 않을 만큼(수십)은 필요.
5. **LLM은 설계 참모지 진실의 주체가 아니다.** 피처 아이디어 ✅, 라벨/검증 ❌. 합성 변주는 넓이 보강만, 검증은 실제로.
6. **앱 로그 기반이라 "출발지"는 로그의 한 필드.** 패킷을 안 본다 → 실제면 IP 별칭으로 1대에 여러 출발지, 합성이면 로그 직접 생성으로 무제한. 인프라 제약이 가볍다.

### 라벨 규칙 (왜 믿을 수 있나)
- 라벨 = **출발지(src) AND 시각(start~end)** 교집합만 그 공격. 그 외 `normal`. → 공격 중 정상 트래픽 보존, 시각만 라벨링의 오염 방지.
- 근거는 **사실 기록**: 합성은 생성기가 start/end·src를 answer.csv에 남기고, 실제는 공격 러너가 기록(`collect_kit`).
- **누수 차단**: IP·UA·pod 이름·공격표식은 **피처로 넣지 않음**.

### 출발지 IP 대역 (연출)
- 정상 `10.16.1.101~`, 공격 각 사건 `10.16.2.11~`(사건마다 고유 IP). 실제 랩은 Kali 보조 IP `10.16.1.211~214`.

### 피처 (9개, v1)
`req_count, max_req_1min, uniq_paths, uniq_objects(소유자원 BOLA), err_ratio, write_ratio, interval_cv, endpoint_entropy, ssh_fail`. v2 후보는 `docs/20` §3.
