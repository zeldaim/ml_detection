## 2. 연계 ① — 룰 기준선과 느린 공격 설계

트러블슈팅 기록에서 확인된 임계치:

| 룰 | 조건 | 레벨 |
|---|---|---|
| 5760 | sshd 인증 실패 (단건) | 5 |
| **5763** (기본) | 같은 출발지 **120초 안에 8회** | 10 |
| **100001** (커스텀) | 5760이 같은 출발지 **60초 안에 5회** | 10 |

**느린 공격 설계값**: 같은 출발지에서 **시도 간격 20초 이상** (예: 20~30초 간격 또는 수 분 간격)
→ 100001(60초 5회)과 5763(120초 8회) 모두 미발동 → 5760(레벨 5)만 쌓임 → **"룰은 침묵, ML은 탐지"** 를 실제 Wazuh에서 재현

> 계산: 8회가 120초 안에 들어가지 않으려면 간격 7개의 합이 120초를 넘어야 한다 → **간격 > 약 17.2초**. 5회가 60초 안에 들어가지 않으려면 간격 4개의 합 > 60초 → 간격 > 15초. 둘 다 만족하고 여유를 두어 **20초 이상**으로 정한다.
> (16초 간격이면 8회가 112초 안에 들어가 5763이 발동한다.) 실제 랩에서 `wazuh-logtest`와 알럿으로 미발동을 먼저 확인할 것.

비교 실험 정의(`03` §3-1) 보완: **룰 기반 탐지 = 100001 또는 5763 발동(레벨 10)**

## 4. 연계 ③ — 엔트로피 자산: 데이터는 파일럿, 코드는 재사용

### 4-1. 데이터 프로파일 (`entropy_log.jsonl`, 2026-10-22 확인)

| 항목 | 값 |
|---|---|
| 전체 길이 | **34분** (2026-05-04 05:50 → 06:24) |
| 정상 구간 | 처음 **약 6.5분** (index 0~292) |
| 공격 구간 | index 293부터 **약 27분 (전체의 약 93%)** — 논문 초안의 "공격 시작 index 293"과 일치 |
| 에이전트 / 공격 | 1개(localhost) / SSH 브루트포스 1회 |
| 한 행의 단위 | 최근 100개 알럿의 엔트로피 (슬라이딩 윈도, 한 알럿씩 이동) |
| 표시 오류 | 4,069건 전부 `phase: "normal"` |

### 4-2. 본 실험 학습 데이터로 쓰기 어려운 이유

1. **공격이 다수(93%)** — Isolation Forest는 다수를 "평소"로 학습 → 공격을 정상으로, 짧은 정상 구간을 이상으로 볼 위험
2. **정상 구간이 현실적이지 않음** — 정상 구간의 출발지 IP 엔트로피가 0(출발지 1개) → 다양한 사용자가 있는 실제 "평소"가 아님
3. **행끼리 독립이 아님** — 이웃한 행이 99% 같은 알럿을 공유 → 4,069행이지만 실제 정보량은 훨씬 적고, 학습하면 성능이 부풀려짐
4. **"누가"를 말하지 못함** — 모든 IP를 섞은 창 단위 값 → 차단(SOAR)에 필요한 IP 단위 판단 불가

### 4-3. 쓸 수 있는 것

| 용도 | 방법 |
|---|---|
| **개념 증명** | "공격이 시작되면 엔트로피가 뚜렷하게 바뀐다" → 보고서·발표의 동기 그림 |
| **엔트로피 계산 코드** (Phase 4) | **가장 큰 자산.** 새 데이터 수집 시 피처 생성기로 재사용, IP 단위로 확장 |
| **피처 아이디어** | Shannon(분포 다양성) + ApEn(순서 규칙성)을 IP별 행동 피처(랩 01)에 추가 |
| **변화 시점 탐지** | 이 데이터는 이상탐지보다 **변화 감지**(임계값, 누적합 등)에 적합 → 별도 소실험 가능 |
| **분석 코드 시험** | 새 데이터가 모이기 전, 정답 재표시(index 293) 후 파이프라인 동작 확인용 |

### 4-4. 본 실험 데이터 요건

- 정상 구간 **수 시간 이상**, 정상 행위 생성기로 다양한 사용자
- 공격 **여러 종류**(빠른·느린·다중 서버) + **정답지**
- 피처는 **IP 단위**(랩 01 방식) **+ 엔트로피**(Phase 4 코드)
- 시간이 부족하면 **공개 데이터로 정상 배경을 채운다** (`05` 데이터 전략)

**연구 연결**: 기존 논문은 "엔트로피가 공격 때 변한다"는 **관찰** → 이번 프로젝트는 IP 단위 엔트로피 피처로 "누가 공격자인지 **자동 탐지**"로 확장.

## 5. 연계 ④ — 그 밖의 자산

- **archives.json(logall)**: 룰에 안 걸린 로그까지 ML 입력 → `03` 주의 ② 방법 B를 1차 실험에 포함 가능. 디스크 사용량 증가 주의(과거 디스크 풀 장애 기록 있음 → 실험 기간만 켜고 로테이션 설정)
- **Persistence T1547**: 시나리오 4를 공개 데이터 재생 대신 **실제 Sysmon 탐지 결과**로 → 리눅스 SSH와 다른 공격 유형까지 포괄
- **terraform-soc**: AWS 모듈(VPC·서브넷·보안그룹·EC2)을 확장해 클라우드 재현 / AWS 워크샵 사전 배포 코드로
- **detection-gaps 문서**: 룰 기반의 한계를 직접 기록한 자료 → 보고서 "왜 ML인가" 근거
