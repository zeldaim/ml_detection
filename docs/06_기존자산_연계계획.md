## 2. 연계 ① — 룰 기준선과 느린 공격 설계

트러블슈팅 기록에서 확인된 임계치:

| 룰 | 조건 | 레벨 |
|---|---|---|
| 5760 | sshd 인증 실패 (단건) | 5 |
| **5763** (기본) | 같은 출발지 **120초 안에 8회** | 10 |
| **100001** (커스텀) | 5760이 같은 출발지 **60초 안에 5회** | 10 |

**느린 공격 설계값**: 같은 출발지에서 **60초 안에 4회 이하** (예: 15~20초 간격 또는 수 분 간격)
→ 100001(60초 5회)과 5763(120초 8회) 모두 미발동 → 5760(레벨 5)만 쌓임 → **"룰은 침묵, ML은 탐지"** 를 실제 Wazuh에서 재현

> 120초 창에 8회가 안 차도록 간격은 **15초 초과**로 둔다(15초 간격이면 120초에 8회 → 5763 발동 위험).

비교 실험 정의(`03` §3-1) 보완: **룰 기반 탐지 = 100001 또는 5763 발동(레벨 10)**

## 4. 연계 ③ — 엔트로피 로그를 ML 학습 데이터로

**데이터**: `entropy_log.jsonl` 4,069건
필드: `timestamp`, `window_size`, `trigger_rule_id`, `trigger_agent`, `phase`, `shannon_rule_id`, `shannon_level`, `shannon_srcip`, `apen_level`

**문제**: 4,069건 전부 `phase: "normal"` — 공격 구간도 normal로 기록됨
**해결**: 논문 초안의 "공격 시작 index 293"을 기준으로 정답 재표시 → 공격 구간 시각·타임스탬프와 교차 확인 후 확정

**실험**
1. 엔트로피 4개 지표를 피처로 Isolation Forest 탐지 → 재표시한 정답으로 채점
2. 룰(100001/5763) 발동 시점과 ML 탐지 시점 비교 → **탐지 시간 차이**
3. 랩 01의 행동 피처(실패 수, 계정 수, 간격 변동계수)와 엔트로피 피처 결합 효과

**연구 연결**: 기존 논문은 "엔트로피가 공격 때 변한다"는 **관찰** → 이번 실험은 "그 변화를 **자동 탐지**한다"로 확장 = 후속 연구.

## 5. 연계 ④ — 그 밖의 자산

- **archives.json(logall)**: 룰에 안 걸린 로그까지 ML 입력 → `03` 주의 ② 방법 B를 1차 실험에 포함 가능. 디스크 사용량 증가 주의(과거 디스크 풀 장애 기록 있음 → 실험 기간만 켜고 로테이션 설정)
- **Persistence T1547**: 시나리오 4를 공개 데이터 재생 대신 **실제 Sysmon 탐지 결과**로 → 리눅스 SSH와 다른 공격 유형까지 포괄
- **terraform-soc**: AWS 모듈(VPC·서브넷·보안그룹·EC2)을 확장해 클라우드 재현 / AWS 워크샵 사전 배포 코드로
- **detection-gaps 문서**: 룰 기반의 한계를 직접 기록한 자료 → 보고서 "왜 ML인가" 근거
