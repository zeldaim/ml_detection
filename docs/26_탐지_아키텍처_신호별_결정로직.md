# 26. 탐지 아키텍처 — 신호↔공격클래스↔(룰/ML/SOAR) 결정 로직

> 로그·지표·SOAR·여러 앱이 붙는 구조에서 **"이 신호로 뭘, 룰로 잡나 ML로 잡나, 대응은 어디서"**를 매번 똑같이
> 판단하는 기준. 새 소스(node_exporter 등)를 붙일 때 이 문서로 자리를 정한다.
> 근거: `docs/19`(원리), `docs/21`(실험), `docs/25`(식별자/귀속), `docs/22`(DB).

## 0. 핵심 원칙 3가지
1. **ML은 한 층이지 전부가 아니다.** 아는 공격은 룰이 실시간 차단, ML은 룰이 놓친 **느린·미지·다변량**을 발견.
2. **신호를 공격 클래스에 맞춘다.** 한 신호가 모든 공격을 보지 않는다(API 로그는 자원공격을 못 봄, 호스트 지표는 BOLA를 못 봄).
3. **임계로 잡히면 룰→SOAR, 못 잡으면 ML.** ML을 억지로 쓰지 않는다(오탐·운영비용).

## 1. 전체 그림 (층)

```
                          [대응]  Shuffle(SOAR) ── 고신뢰=자동, 나머지=사람 티켓
                                      ▲
            ┌──────────────┬──────────┴───────────┬────────────────┐
         [경계/실시간]   [행위/준실시간]        [호스트/상관]      [가용성/자원]
          WAF·룰          ML(IF/LOF/AE/RF)        Wazuh/SIEM         Prometheus
          아는 공격 차단   느린·미지 발견          호스트 이벤트·룰    지표 임계/ML
             ▲                 ▲                      ▲                 ▲
          ───┴─────────────────┴──────────────────────┴─────────────────┴───  [수집]
          API GW/nginx 로그   인증·세션(JWT)        Wazuh 에이전트      node_exporter
          (L7 API 행위)       (식별·UEBA)           (FIM·룰·로그)       (CPU·메모리·네트워크)
                                   │ (로그만 필요하면 Logstash/Filebeat 로 수송)
```

> 경계/실시간 층의 **WAF 구현은 `docs/31`**(nginx + ModSecurity + OWASP CRS). FortiGate는 경계 정책·IPS, ModSecurity는 HTTP 내용 검사로 나눈다.

## 2. 신호 → 공격 클래스 → 처리 (지도)

| 신호(소스) | 보는 것 | 주 공격 클래스 | 처리 |
|---|---|---|---|
| **API GW/nginx 액세스 로그** | 메서드·경로·상태·출발지·시각 | BOLA·SQLi·대입·열거·수집(**로직**) | **ML(행위)** + 레이트 룰 |
| **인증/세션 이벤트**(JWT sub) | 로그인·OTP·사용자 | 계정탈취·크리덴셜스터핑 | **ML(UEBA 상대피처)** + 룰 |
| **호스트 지표**(node_exporter) | CPU·메모리·네트워크·디스크 | DoS·자원고갈·마이닝·유출(**자원/가용성**) | **뻔하면 Prometheus 임계→SOAR, 미묘·다변량이면 ML** |
| **Wazuh 에이전트** | FIM·rootcheck·호스트 로그 | 호스트 침해·설정변경·무결성 | **Wazuh 룰** + 상관 |
| **WAF(ModSecurity) 감사 로그** | 요청 단위 규칙 적중·이상 점수 | SQLi·XSS·LFI·RCE(**내용/아는 패턴**) | **WAF 실시간 차단**. ML 피처로는 안 넣고 "WAF vs ML 무엇을 잡았나" 비교용 (`docs/31` §6-3) |

> **node_exporter 지표는 "나쁜 피처"가 아니라 "다른 공격용 좋은 피처".** API 로직엔 무신호지만 자원/가용성 공격엔 유효.

## 3. 결정 로직 (새 신호 붙일 때마다)

```
새 신호가 들어오면:
  1) 이 신호로 '어떤 공격'을 잡나? (공격 클래스 지정 — 사람 판단)
  2) 그 공격이 단순 임계/룰로 잡히나?
        예   → 룰/Alertmanager → Shuffle(SOAR)      ... ML 안 씀(싸고 설명가능)
        아니오(느림·미지·다변량) → ML 피처로 추가     ... 윈도우 피처 or 시계열
  3) 라벨은? 통제 공격의 '사실'로 생성(출발지 AND 시각). LLM/추측 금지(docs/19 §7)
  4) 출발지 귀속 되나? (NAT/프록시면 사용자/세션 키로 — docs/25)
```

## 4. ML이 받는 입구 (피처 소스별)
- **구현됨**(확정 피처셋은 `ml/feature_spec.py`, `docs/27`): nginx/archives 로그 → `ml/features.py`(웹 `web_v1` 10 = 행위 8 + rel 2), MySQL general log → `edge/db_features.py`(DB 피처 8), UEBA 상대피처 `ml/relative_features.py`.
- **입구 추가 필요(미구현)**:
  - 인증 이벤트 → 사용자 키 피처(로그인 실패수·OTP 시도 등). (NAT 실측 §25 에서 X-Lab-User 로 원리 확인)
  - ~~호스트 지표(node_exporter) → 시계열 피처 추출기~~ → **구현됨(2026-10-25)**: `edge/host_metrics.py`(Prometheus API·저장 JSON·/metrics 스냅샷 → `host_v1` 12피처).
    로그와 다른 모델 = **호스트별 기준선 LOF**(통합 모델은 느린 유출 0/12, 호스트별 12/12 — 합성). `docs/27` §3.
- 공통 규칙: **원문(쿼리·페이로드·IP·UA)은 피처로 안 넣는다**(누수·민감정보). 숫자로 요약(`edge/` 원칙).

## 5. 대응(SOAR) 규칙 — 오탐을 전제로
- **ML 경보로 자동 차단 금지(기본)**: 오탐이 정상 유저를 끊는다(§L 오탐 존재). 
- **고신뢰만 자동**(여러 모델 합치·룰과 교차확인), **나머지는 사람 티켓**(Shuffle 워크플로).
- 파괴적 동작(차단·격리)일수록 **사람 확인** 게이트. 조회·태깅은 자동 OK.

## 6. 이 아키텍처가 답하는 질문 (예)
- *"node_exporter 붙이는데 ML이냐 SOAR이냐?"* → 뻔한 자원 임계면 Prometheus→Shuffle, 미묘한 다변량이면 ML 피처. (둘 다 가능)
- *"Wazuh 다 달아야 하나?"* → ML용 로그만이면 Logstash/Filebeat 수송으로 충분. 호스트 보안(FIM·룰)까지면 Wazuh 에이전트.
- *"새 앱 로그 붙이면?"* → §3 로직대로: 공격클래스 지정 → 임계면 룰, 아니면 ML 피처 → 라벨 생성 → 귀속 확인.

> 한 줄: **신호마다 "어느 공격·룰이냐 ML이냐·대응은 어디" 를 §3 로직으로 정한다. ML은 '느림·미지·다변량' 전담, 뻔한 건 룰→SOAR, 자동차단은 고신뢰만.**
