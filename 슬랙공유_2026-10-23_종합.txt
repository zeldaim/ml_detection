:bar_chart: Wazuh 룰로 못 잡는 이상행위, ML로 잡기 — 랩 실험 결과 (2026-10-23)

환경: Juice Shop + nginx (Wazuh 없이), 정상 6 IP 40분(37구간) + 공격 4건
      — 빠른 로그인대입 ×2(A1·A2), BOLA ×2(B1 빠름 / B2 느림). contamination 0.05 고정.

한 줄 요약: 느린 공격은 룰·RF·IF 모두 놓쳤지만 LOF가 잡았다.
           → IF + LOF + RF를 같이 써야 한다는 근거 확보 :white_check_mark:


① 처음 보는 공격 탐지율 (E2 — 종류를 통째로 빼고 학습. 정상 오탐은 전부 0%)

    RF            0.29  (2/7)   ← 배운 공격만 암, 처음 보는 건 놓침
    IF            0.43  (3/7)   ← 느린 BOLA 놓침
    LOF           1.00  (7/7)   ← 느린 것까지 다 잡음
    IF | LOF      1.00  (7/7)   ← 합치면 완벽

    :point_right: IF가 놓치고 LOF가 잡은 구간 4개 = 느린 BOLA.
       "LOF가 IF의 약점(국소 이상치)을 보완한다"(가설 H5) 실제 확인.
       이유: 느린 BOLA는 분당 6회라 전체적으론 안 튐 → IF는 놓치고, LOF는 밀도로 잡음.


② RF가 공격 "종류"까지 맞히나 (3지선다: 정상 / 대입 / BOLA)

    빠른 대입 (A1·A2)   → 대입   :white_check_mark:
    빠른 BOLA (B1)      → BOLA   :white_check_mark:
    느린 BOLA (B2)      → 정상   :x:  (포착 자체를 못 해서 분류 불가)
    종류 정확도 3/7

    :point_right: 포착된 공격은 종류를 정확히 구분 (대입↔BOLA 혼동 0건).
       단, 못 보는 공격은 분류도 못 함 (느린 BOLA는 요청 수가 정상과 비슷).


③ 결론 — 탐지 2층 구조

    1층 발견 : LOF / IF (비지도)  — "평소와 다르다"
    2층 분류 : RF (지도)          — "이건 대입이다 / BOLA다"

    한쪽만으로는 부족.
    - RF만  → 처음 보는/느린 공격은 발견도 분류도 못 함
    - IF/LOF만 → "이상하다"는 알지만 무슨 공격인지 모름
    - 둘을 합쳐야 → 느린 공격까지 발견 + 종류 식별

    RF가 본 피처(중요도): err_ratio 0.31, uniq_objects 0.15, endpoint_entropy 0.13
